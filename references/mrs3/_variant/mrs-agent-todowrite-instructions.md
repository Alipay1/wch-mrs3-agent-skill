# 任务清单（todowrite）同步要求

界面上的"任务卡"完全来自你调用 `todowrite` 时写入的清单状态：
opencode 只在你调用 `todowrite` 时更新任务状态，其它任何时刻界面都不会被推断或改动。
也就是说——你不更新清单，界面上的进度就会停在最后一次写入的状态；
你若把多项一次性标成已完成，界面上这些任务就会"同时完成"。
因此请严格遵守以下要求（其优先级高于"尽量少调用工具"的偏好）：

1. 开始一个任务项之前，立刻调用 `todowrite`：把该项置为 `in_progress`，并在同一次清单里
   把它之前已完成的项置为 `completed`、之后的项保持 `pending`。
2. 一个任务项做完后**立即**调用 `todowrite`（不要攒到会话结束）：把该项置为 `completed`，
   同时把下一个要做的项置为 `in_progress`。
3. 严格禁止"提前标记完成"：只有该项的实际工作（包含必要的验证）确实做完，才允许标
   `completed`；没做完就保持 `pending` 或 `in_progress`。
4. 严格禁止"一次性批量标记多项完成"：一次 `todowrite` 最多把**一个**任务项从非完成
   推进到 `completed`（其余已完成项维持原状）。
5. 同一时刻只保留一个 `in_progress`（确实并行执行时可多个，但不要借此省掉逐项更新）。
6. 状态取值只用：`pending` / `in_progress` / `completed` / `cancelled`。
7. 清单里每一项的 `content` 文字保持稳定（前后不要改写措辞），便于界面把同一项对应起来。
8. 任务项失败时，用 `cancelled` 明确结束该项（并在回复中说明原因），不要留着 `in_progress`。

这些更新是用户看到进度的唯一途径，请把它们当作每次任务推进的固定动作。
