# MRS 代码生成前：验证方案与硬件连接表检查

## 目标
在**创建 / 生成代码之前**，先把「本次要写什么代码、之后怎么验证、验证所需外部硬件怎么接」一次性规划清楚并让用户确认，确认通过后再生成代码：

工程代码分析 → 规划全局方案 → **输出「验证方案 + 硬件连接表」并一次性弹框确认（★ 全程唯一一次交互）** → 冻结硬件连接表（不再交互） → **新建 / 打开工程并执行代码生成（此前禁止建工程）** → 验证阶段调用 `mrs-external-tools`。

> 本技能是**前置门禁技能**：只负责「生成前」的规划与确认；工具的实际查询 / 安装 / 调用（含单实例 / 多实例判定）一律由 `mrs-external-tools` 负责，本技能**禁止**直接调用工具。

> **占位符约定**：本文 `<...>` 均为**占位符**（如 `<引脚号 + 引脚名>`），**不是**可照抄的取值；真实取值**只能**来自实时枚举结果、工程配置 / 原理图、`mrs-external-tools` 的工具缓存与手册，或用户输入。

## 使用场景判断（前置检查，不满足则跳过）
**本技能专属门禁**：用户需求**必须**是「生成代码」类需求（创建 / 生成 / 编写 / 修改代码）。**只按用户需求判断，与实际有没有真的生成代码无关**：即便本次流程最终并未实际产出代码（被后续步骤代为实现、被其他原因中断等），只要用户需求本身属于生成代码，即视为满足。纯查询 / 纯文档 / 纯分析类需求 → **跳过本技能**。
**共用检查**：再按下方**共用检查逻辑 C1** 判定（① 后续会使用工具验证 + ② Windows 平台）。C1 满足 → 执行本技能；① 不满足 → **跳过本技能**并简要说明；② 不满足 → 说明平台限制，**禁止**强行调用。

## 共用检查逻辑 C1–C4（场景检查 + 硬件连接检查）
> 本节在 `mrs-prepare-verify` 与 `mrs-external-tools` 中**逐字一致**，是两者**唯一**的检查依据；**任一技能执行过即视为已完成，另一技能必须跳过、不得重复检查**（见 C4）。

**C1 场景检查（是否进入工具验证流程）**
- ① 本次流程**确实会使用**工具（USB / 串口 / 蓝牙 / 以太网等）验证代码 / 硬件效果。
- ② 平台须为 **Windows**；非 Windows → 说明平台限制，**禁止**尝试调用或安装。
- ③ 暂时**无法判断** ① → 并入流程开始的**同一次合并询问**确认，**禁止**反复弹框。
- 判定：①+② 满足 → 进入 C2 / C3；① 不满足 → **不做设备验证**（与设备验证无关的工具查询 / 安装等请求可继续）；② 不满足 → **终止**并说明限制。**默认判定（强制）**：请求为**纯编译 / 无外设交互**（不涉及 USB / 串口 / 蓝牙 / 以太网等外部设备）时，**直接归为「不做设备验证」**，**不得**据此弹框或输出硬件连接表。

**C2 设备枚举检查（必须实时、真实可用）**
- **必须**用 `bash`（Windows 用 PowerShell）**实时枚举**并与当前实际设备实例交叉印证：串口 `Get-PnpDevice -Class Ports -Status OK` / `Get-CimInstance Win32_SerialPort` 与 `[System.IO.Ports.SerialPort]::GetPortNames()` 相互印证；USB `Get-PnpDevice -Class USB -Status OK`；网卡 `Get-NetAdapter | Where-Object Status -eq 'Up'`；蓝牙须为当前实际存在且可用的控制器：用 `Get-PnpDevice -Class Bluetooth -Status OK` 实时枚举（可用 `Get-CimInstance Win32_PnPEntity` 交叉印证）并结合蓝牙服务（`Get-Service bthserv, BTAGService`）状态判定，**禁止**把已禁用 / 已拔出 / 隐藏的幽灵适配器当作可用。
- **禁止**把**历史记录 / 缓存 / 注册表残留 / 已拔出 / 已移除 / 已禁用 / 隐藏设备**等**幽灵设备**当作可用设备；候选列表**必须**来自实际枚举结果，格式 `<实际标识> (<实际设备描述>)`，**禁止**凭空输入或照抄示例。
- 枚举结果为空或**无法确认**某设备当前真实存在 → **禁止**使用该设备，**必须**如实报告并终止，或请用户重新连接 / 确认。
- **需要烧录 / 下载时**（含「必须先下载才能验证」）：**必须**实时枚举一次 **WCH-Link 下载器**（外置 WCH-Link 与评估板**板载 WCH-Link** 均按 WCH-Link 处理；用 `Get-PnpDevice -PresentOnly -Status OK` 匹配设备描述含 `WCH-Link` 者，并与 `Get-PnpDevice -Class USB -Status OK` 交叉印证）；结果**只用于 C5 的 WCH-Link 确认**，**不写入硬件连接表、不逐引脚展开**；枚举为空 / **无法确认** → **禁止**下载，如实报告并终止（**禁止**用历史记录 / 幽灵调试器顶替）。

**C3 硬件连接检查（硬件连接表规范：全局约定 + 文字说明 + 图示意）**

- **表的定位（强制）**：输出物统一称**硬件连接表**，它**必须覆盖本次验证用到的全部硬件连接**。**取消「需要接线 / 无需接线」分类**：**凡是必须建立的物理连接一律同权、同格式、逐条列出**——引脚跳线 / 转接 / 外接模块与**板载 USB 口 / 板载调试口 / 网口 / 内置无线等全部同列**；**禁止**把板载口 / 网口 / 内置模块当作「不用接线」而漏项 / 合并 / 省略，**禁止**只列跳线项。
- **结构（三部分，顺序固定，缺一不可）：① 全局约定 → ② 文字说明 → ③ 图示意**（**分工**：图 = 电气连接、**与板版本无关**；文字 = 物理落点、**随评估板版本变**——丝印 / 针位 / 板版本 / 依据）：
  - **① 全局约定**：置于**表首**，全表**只写一次**，任何一项都不得省略——**共地**（`GND ↔ GND`）；**供电来源**（MCU 与对端各由谁供电）；**电平匹配**（3.3V / 5V、是否需电平转换）；**建议接线顺序（先共地 → 再信号 → 最后电源）**。
  - **② 文字说明**：**一条 = 一个连接项**，分**主行 + 子节点**两层（**只允许一层子节点，不做三级缩进**）：**主行只写四样、必须一行、尽量短**——`□ [<线号>]线 <MCU 侧引脚号> <引脚名> → <对端口 / 引脚号> <引脚名>（方向）—— <一句话语义>`，**禁止**在主行堆丝印 / 依据 / 参数 / 长解释；**线号一律写成 `[W1]线`（方括号包裹线号 + 其后加「线」字）；线号整段不加反引号（避免深色背景），其余关键标识仍用反引号高亮**；MCU 侧引脚号为空（如 `GND`）时同样写 `□ [W5]线 GND →…`，**禁止** `□ W5 GND …` 这类线号与引脚名连读的写法；**子节点必须是缩进一层的 Markdown 子列表项**（父行 `- □ [W1]线 …`，子行 `  - └ 丝印：…`）——**仅用前导空格缩进会被 Markdown 折叠为主行同级（顶格），判为错误**——`  - └ 丝印：<板版本> <物理丝印名 + 针位>…（依据：<文档 / 页>）`，**丝印落点必填**（唯一例外：按本节「丝印前置门槛」判定依据文档**确实查不到**时，该连接项**不写**丝印子节点）、多板版本**并列全列**，USB 场景另可加 `  - └ 端点：<地址 / 方向 / 类型 / 包长>`；**层级红线（强制、可机检）**：**层级（缩进）是强制结构、不是可选项**，丝印 / 依据 / 端点信息**一律不得出现在主行**——**主行内出现 `丝印`、`依据`、`端点` 字样即判定层级放错**，必须下沉为缩进子节点；**禁止**子节点与主行同列、**禁止**写进主行末尾、**禁止**用 `；` / `,` 并进主行；**简洁红线**：语义**限一句话**、主行 **≤ 80 字符**（超长即下沉为子节点）；与图中线号**一一对应、同名同数**；板载 USB 口 / 网口 / 内置无线等**同样按此格式写成正常连接项**，**禁止**写成「无需接线」这类豁免描述。
  - **② 正 / 反例（层级示范，实际输出必须照此两层层级）**：
    - ✓ 正确（主行顶格 + 子节点为缩进一层的子列表项，渲染可见缩进）：
      ```
      - □ [W1]线 `PA2` `USART2_TX` → 对端 CH340 `RXD`（输出）—— 目标板串口发往 PC
        - └ 丝印：`CH32V307EVT`=`P6`/`P7`/`P9`（依据：评估板说明书「MCU I/O 口」）
      ```
    - ✗ 错误①（丝印与主行同级、缺缩进与 `└ `）：
      ```
      - □ [W1]线 `PA2` `USART2_TX` → 对端 CH340 `RXD`（输出）—— 目标板串口发往 PC
        丝印：`CH32V307EVT`=…（依据：…）
      ```
    - ✗ 错误②（丝印并进主行同一行）：
      ```
      - □ [W1]线 … —— 目标板串口发往 PC  丝印：…（依据：…）
      ```
    - ✗ 错误③（子节点仅用前导空格、无列表标记 → Markdown 折叠为顶格）：
      ```
      - □ [W1]线 `PA2` `USART2_TX` → 对端 CH340 `RXD`（输出）—— 目标板串口发往 PC
        └ 丝印：`CH32V307EVT`=…（依据：…）
      ```
  - **② 重点突出（强制）**：文字说明中所有**关键标识**——**物理丝印名（丝印号）**、**引脚号**（MCU 侧与对端侧均含）、**子节点里的丝印名与依据**——**一律用半角反引号成对包裹为行内代码**，借助其渲染出的**深色背景**突出显示（示例：`P6`、`PA9`）；**线号除外**——线号统一以 `[W1]线` 形式写出，**整段不加反引号、不显示深色背景**，方括号 `[ ]` 与「线」字保持纯文本；**禁止**仅靠加粗替代、也**禁止**不加任何强调地埋在普通文本里（线号不受此限）；同一标识在**主行、子节点与图示意**中**必须一致**（图示意为纯 ASCII，**不加反引号**，只保证标识字符相同）。
  - **③ 图示意**：纯 ASCII（只用 `< > - | +` 与半角空格）画出**全部连接项**，且**全部连接项合并为同一张连续图**（**整表唯一图**：全表**只输出这一张图**，任何情况下**不得**出现第二张图 / 分图 / 每卡一图）（逐行排列，**禁止**按对端设备 / 子系统 / 接口分段，**禁止**用空行、小标题或分块把一张图拆成多段）；固定三段式 `MCU 侧标注 →（线号 + 方向）→ 对端侧标注`；**图首必须独占一行标注两端身份**——左列表头固定写 `MCU侧`（即目标板 MCU 侧）、右列表头写 `对端`（**对端唯一**时写**该对端实际身份**，如 `CH340` / `PC` / `RJ45`；**对端不唯一**时表头固定写 `对端`，且**每行右侧**须写 `<对端设备> <引脚名>` 以区分），两表头分别与下方左、右列左对齐（示例首行：`MCU侧                    对端(CH340)`）；该表头是**整张图唯一的表头**，**不是**「小标题」、不得据此把图拆段；**MCU 侧只写 `<引脚号> <引脚名>`（引脚号为空时只写引脚名，如 `GND`），不写丝印 / 针位**——丝印随评估板版本变，统一放 ② 文字说明；**线上只标线号与方向**（如 `--W1-->` / `<--W2--`），**禁止**在图上出现任何**功能描述**（发送 / 接收 / 交叉 / 共地 / 依据 / 参数等一律不进图）；**必须含 GND 线**（线上不写「共地」字样）；**图内标注一律 ASCII**；**每行 ≤ 72 字符**；**通信参数 / 依据来源不进图**。
- **卡片标题（每张卡片一行，属文字说明的标题）**：**接口 / 对端设备 + 通信参数**；**该行必须整行加粗**（Markdown `**…**` 包裹）。
- **卡片内顺序（强制）**：每张卡片**只**按「**卡片标题 → 文字说明**」排列，**卡片内不得出现任何图**；**整张硬件连接表全程只允许存在一张图**（即 ③ 图示意，**唯一图**），该图**必须置于全部卡片文字之后、统一输出一次**，**禁止**每张卡片各画一张图、**禁止**图与卡片文字交错、**禁止**出现第二张图 / 重复图 / 分图。
- **板版本不明→全列（禁止询问）**：板版本不明确时**禁止询问用户**，必须依据评估板说明书 / 原理图**直接列出所有已知板版本**（如 R1 / R2 / R3、旧版 CH32V307EVT、CH32V303EVT）对该接口的丝印名与 MCU 引脚对应，在硬件连接表中**并列完整呈现**，由用户自行对号入座；仅当版本已明确时才只列对应版本。
- **数据来源（强制）**：外设 / 引脚 / **物理口丝印** / 板版本等信息**必须**来自**实际查阅过**的**评估板说明书 / 原理图**（或工程原理图、芯片数据手册），并在硬件连接表中**注明依据来源**（哪份文档 / 哪个文件、哪一页 / 哪个网络名）；**禁止**未查阅就先规划或先写硬件连接表，**禁止**凭记忆 / 凭示例 / 凭推测臆造；查不到 → **如实说明并列为不确定项**，**禁止**编造（**丝印例外**：丝印确实查不到时按本节「丝印前置门槛」例外处理——该连接项**不写**丝印子节点，且**表内表外均不提**、不留任何「未查到 / 不确定」痕迹）。
- **禁止模糊表述**：「连接到串口 / 接到电脑 / 接上调试器」这类写法**一律禁止**；板载口（USB / 网口 / 调试口等）**必须写明物理丝印名**（如 `P6` / `P7` /「网口」）并给出其对应 MCU 引脚，**禁止只写「板载口」**。
- **串口（UART）人工接线必须「收发引脚逐一对应」**：**必须**逐条列出 `TX（引脚号 + 引脚名）↔ 对端 RX（引脚号 + 引脚名）`、`RX（引脚号 + 引脚名）↔ 对端 TX（引脚号 + 引脚名）`（**收发必须交叉**）、`GND ↔ GND`；有流控时补 `RTS ↔ CTS` / `DTR ↔ DSR`，RS-485 补 `A ↔ A` / `B ↔ B`；并注明电平制式（TTL / RS-232 / RS-485）与波特率 / 数据位 / 停止位 / 校验位。
- **可枚举确定的连接**（设备 + **VID / PID** 等）→ **可略过**逐引脚确认，但**必须**写明枚举到的**实际设备**；**仅当该连接项由枚举即可完全确定、且不含人工跳线时才可略过**：若用 USB 转串口模块跳线接到目标板 UART 引脚，仍按上条**逐引脚**确认。
- **弹框（先完整展示 → 再弹框；弹框必须自包含整表，且即 C5 的唯一一次交互）**：
  - **先完整展示「全局约定 + 文字说明 + 图示意」，再发起确认**（顺序**禁止颠倒**）；**弹框能合并的必须合并**（同一模块 / 同一组连线一次性列全）。
  - **弹框正文必须逐行照录整张硬件连接表**（全局约定 + 文字说明的**主行与子节点** + 图示意，**一行不省**），且**必须保留「主行顶格 + 子节点为缩进一层的子列表项（`  - └ 丝印：…`）」的两层层级**（**禁止**为省篇幅拍平 / 合并 / 改用 Markdown 表格）：**禁止**只放摘要、**禁止**用省略号或「等 / 略 / 同上 / 其余同表」概括、**禁止**合并行 / 折叠、**禁止**写「详见上一条 / 见上面」、**禁止**只放在弹框之前的正文里（弹框 / 选项卡会遮挡前置内容）；选项只承载「**硬件连接是否已就绪**」这类**短决策**。
  - **逐项自检（强制；未通过禁止输出、禁止弹框）**：输出硬件连接表后、发起弹框前**必须逐项自检**，**每项都必须为「是」**，任一项为「否」→ **原地修正并重新自检**，**禁止**带未通过项进入弹框，**禁止**跳过自检或只写「已自检」：
    1. 图示意**每一行**是否**同时含** MCU 侧标注 + 线号 + 方向 + **对端侧标注**（三段式缺一不可，**尤其不得只画 MCU 侧、漏画对端侧**）；
    2. **图的线号数 = 文字说明主行条数**（**子节点不计入条数**，但**必须逐行照录**），引脚数一并对齐；
    3. 每一根线「从哪根针 → 到哪根针 + 方向」均可核对，且与 ② 文字说明**同名同数**；
    4. 图上**无任何功能描述**（功能描述出现即为放错位置）；
    5. 每个连接项**都有丝印子节点，且该子节点为缩进一层的 Markdown 子列表项**（**父行 `- □ [W1]线 …`、子行 `  - └ 丝印：…`，渲染可见缩进**；物理丝印名 + 针位），**板载 USB 口 / 网口 / 调试口 / 内置模块亦不例外**；**子节点仅用前导空格缩进（折叠顶格）、与主行同列、或并进主行 → 判否**（**例外**：按「丝印前置门槛」判定为**依据文档确实查不到丝印**的连接项，**不写**丝印子节点，**不算缺项**，本项仍判「是」）；
    6. 用户**只看到该弹框、不往上翻任何内容**，即可核对表首全局约定与每一根线。
    7. **主行内是否不含 `丝印` / `依据` / `端点` 字样**？（含即判定层级放错 → 判否，必须下沉为缩进子节点）
    8. **全表是否只有唯一一张图**？（出现 ≥2 张图、每卡一图、或按接口 / 对端分图 → **判否**，必须先合并为唯一图再重新自检）
  - **丝印前置门槛（强制，未过禁止弹框）**：发起弹框前**必须逐条**检查**每个连接项是否带有丝印子节点**，且该子节点已写明 **物理丝印名 + 针位**；**板载 USB 口 / 网口 / 调试口 / 内置模块一律不得省略**，**禁止**只写 MCU 引脚号而不写其物理落点。**任一条连接项缺丝印子节点 / 丝印缺失 / 仅写「板载口」→ 禁止发起弹框，必须先补齐丝印再重新输出**（板版本不明按「板版本不明→全列」并列全列）。**例外（不阻断）**：**实际查阅**评估板说明书 / 原理图后**确实查不到**该连接项丝印时，该连接项**不写丝印子节点**——**既不写占位符，也不写任何推测性落点**（`未知` / `需用户对照板子 / 原理图确认` / `就近 GND 排针` 之类**一律禁止**），且**表内表外均不留任何痕迹**（**禁止**写「未查到 / 不确定 / 待确认 / 需用户核对」等任何说明），该连接项直接**放行、不阻断弹框**。**例外不得滥用**：凡依据材料中查得到的丝印（尤其板载 USB 口 / 网口 / 调试口 / 内置模块）**一律必须写**；**仅在已实际查阅且材料中确实没有**时方可省略，**禁止**未查阅就省略，**禁止**为凑丝印而编造或臆测。
- **确认后冻结**：用户确认后引脚 / 外设 / 对端设备**冻结**；确需变更 → **必须重新确认**。
- 用户否定 → 修正后**重新确认**；无法确认 / 连接不可行 → **终止流程**。

**C4 去重规则（做过即不重复检查）**
- `mrs-prepare-verify` 在生成代码前执行 C1–C3；**若它已完成，`mrs-external-tools` 必须跳过 C1–C3**：**禁止**再次弹框询问设备连接 / 接口选择，**禁止**重复枚举，直接沿用其**验证方案与硬件连接表**进入工具查询。
- **未经 `mrs-prepare-verify`（或它只做了一部分）**时，`mrs-external-tools` **按同一份 C1–C3** 执行。
- **跳过 ≠ 允许幽灵设备**：实际使用前若发现设备**不存在 / 不可用 / 与硬件连接表不一致**，**必须**如实报告并终止（必要时回到 `mrs-prepare-verify` 重新确认），**禁止**用历史记录或替代设备顶替。

**C5 单次交互规则（★ 全程只与用户交互一次）**
- **整流程只允许一次用户交互**：把「**验证方案确认**」「**硬件连接已就绪确认**」**合并进同一次弹框**；**禁止**拆成两次、**禁止**跨轮追问、**禁止**零散反复弹出。
- **顺序不变（禁止颠倒）：先输出 → 再弹框**——弹框前**必须**已把**验证方案全文 + 硬件连接表（C3 规范）**完整写出；弹框正文**必须逐行照录**上一步已输出的**硬件连接表全文**（见 C3），**禁止**只放摘要、**禁止**缩写 / 省略 / 合并。
- **弹框二合一**：① **验证方案**（接受 / 自行输入 / 不接受即终止）；② **硬件连接已就绪确认**（是否已按**硬件连接表全文**逐条就绪，含**表首全局约定（共地 / 供电 / 电平 / 接线顺序）、文字说明逐条连接项与图示意**）；正文**必须完整包含硬件连接表全文**（逐行照录，**禁止**缩写 / 省略 / 合并）。
- **蓝牙追加确认（仅当本次涉及蓝牙 / BLE 功能时强制；追加在弹框最后一项）**：凡第 1 步工程代码分析发现**蓝牙 / BLE 功能**（BLE 外设初始化、蓝牙协议栈 / GATT 服务、蓝牙透传 / 收发接口等），或本次验证需用**主机侧蓝牙适配器**与目标板通信时，**必须**在「验证方案确认 + 硬件连接已就绪确认」二合一正文与选项**之后**、弹框**末尾**追加**确认内容**：
  - **正文追加**：`蓝牙适配器已连接：<C2 实时枚举到的实际蓝牙适配器（实际标识 + 实际设备描述 + 状态）>`；枚举为空 / 无法确认 → **禁止**写「已连接」（**禁止**幽灵适配器），**必须**按 C2 如实报告并请用户接入 / 启用适配器后在**同一轮内**重新枚举再确认。
  - **选项追加（该弹框的最后一项短决策）**：**「蓝牙适配器已经连接（已逐条核对上述实时枚举结果）」**——是 / 否；为**否** → 请用户接入 / 启用后在**同一轮内**重新确认，仍无法确认 → **终止流程**。
  - 该项**必须**并入本次唯一一次弹框，**禁止**单独弹框、**禁止**跨轮追问、**禁止**省略，**禁止**用「蓝牙正常 / 蓝牙可用」等模糊表述代替。
- **WCH-Link 追加确认（仅当本次涉及烧录 / 下载时强制；追加在弹框末尾，蓝牙追加确认之后）**：凡本次需**烧录 / 下载 / 复位**才能完成验证，**必须**在「验证方案确认 + 硬件连接已就绪确认」正文与选项**之后**、弹框**末尾**追加：
  - **正文追加**：`WCH-Link 下载器已连接：<C2 实时枚举到的实际 WCH-Link（实际标识 + 实际设备描述 + 状态）>`；枚举为空 / 无法确认 → **禁止**写「已连接」，**必须**如实报告并请用户接入后在**同一轮内**重新枚举再确认。
  - **选项追加（该弹框的最后一项短决策）**：**「WCH-Link 下载器已经连接（已核对上述实时枚举结果）」**——是 / 否；为**否** → 请用户接入后在**同一轮内**重新确认，仍无法确认 → **终止流程**。
  - 该项**独立于硬件连接表**：**不要求**列出 WCH-Link 的具体连接（调试引脚 / USB 口不在表内展开），**禁止**据此扩展 C3。
  - **同时涉及蓝牙时排序**：蓝牙追加确认在前、WCH-Link 追加确认在后（仍属**同一次弹框**）；**禁止**单独弹框、**禁止**跨轮追问、**禁止**省略。
- **同轮补全例外**：发起确认前若存在无法确定的关键配置，**允许在同一轮内先问配置 → 拿到答案后立即补全接线指引并确认**；只要用户**最终只经历一轮**；**禁止**先问配置、隔一轮再问接线。
- **已确认即不重复**：若本次流程已由 `mrs-prepare-verify` 完成过本规则的一次交互，`mrs-external-tools` **必须跳过、不得再弹框**（见 C4）。
- **确认后冻结**：方案与接线一并冻结（见 C3）；此后**不得**再向用户发起任何询问；确需变更 → **重新走一次**本规则（新的一次交互）。
- **自检**：用户**只看到这一次弹框、不往上翻任何内容**，也能同时知道「验证方案是什么」「**表首全局约定**」「每一根线从哪根针接到哪根针、方向是什么」以及**文字说明里的丝印落点**（丝印落点须位于**缩进一层的子列表项（`  - └ 丝印：…`，渲染可见缩进）**、而非与主行同级或仅用空格缩进；按 C3 例外省略丝印的连接项不受此限）；做不到即为**放错位置**。

## 网络检测 N1–N5（工程含网络接口 / 以太网模块时执行；仅本技能执行，结果随方案转交）

> **触发条件**：第 1 步工程代码分析发现**网络接口或以太网模块**（ETH 外设初始化、MAC / PHY 驱动、以太网收发接口等）。不满足 → **跳过本节全部内容**。
> **定位**：本节是本技能**专属**的网络检测扩展（C2 / C3 在以太网场景的细化），**不改动 C1–C5 原文**；`mrs-external-tools` **不收录**本节，它按 C4 / C5 直接复用本节结论。本节的网卡枚举即本次 C2 的网卡枚举结果，**禁止重复枚举**。
> **交互约束（遵从 C5）**：本节的连接关系问询（N2）与网卡选择（N3）**必须并入 C5 唯一一次交互**（作为**同轮补全**：先问 → 拿到答案后补全方案与硬件连接表 → 同一次弹框确认），**禁止**单独弹框、**禁止**跨轮追问；非 192.168 开头的 IP 设置问询与路由分歧调整问询同样并入该次交互。
> **实现约束**：本节所有算术与规则判定（网卡数量、接收字节数比较、同网段判定、候选静态 IP 生成、路由分歧判定）**一律用下方 PowerShell 脚本完成**，**禁止**模型心算或臆断；**全部脚本只用 PowerShell，禁止使用 Python**。片段含中文注释，另存为 `.ps1` 时**必须存为 UTF-8 with BOM**（Windows PowerShell 5.1 兼容要求，与 `mrs-external-tools` 第 0 节约定一致；**实测**：无 BOM 时 5.1 按 ANSI 误读中文注释，可能把相邻代码行吞入注释，导致赋值静默失效）；直接以 `-Command` 内联执行则不受影响。

### N1 协议栈判定（决定是否需要 IP 配置与网络工具验证）
扫描工程源码，判断固件是否包含**网络协议栈（TCP / UDP 模块）**（如 socket / tcpip / lwIP 等协议栈初始化与 TCP / UDP 收发调用）：
- **含协议栈** → 设备需要 IP 配置 → 依次执行 N2–N5；
- **不含协议栈**（典型：USB 转网卡、网络模块仅提供接口收发**原始以太网帧**）→ **不需要配置 IP，不做 N2–N5、不纳入网络工具验证**；在验证方案中写明「无协议栈，仅以太网帧收发，不纳入网络工具验证」，按常规外设验证流程继续。

### N2 连接关系问询（并入 C5 唯一一次交互，禁止单独弹框）
问询用户：**设备与当前电脑之间的网络连接关系**，二选一：
- **A**：设备**经路由器 / 交换机**与当前电脑同网连接；
- **B**：设备**经当前电脑的另一个网卡（网卡 B）直连**。
该问询**必须并入第 2 步 C5 的唯一一次弹框**（作为**同轮补全**：先问连接关系 → 拿到答案后立即补全方案与接线指引 → 同一次弹框确认），**禁止**单独弹框、**禁止**跨轮追问；用户无法确定 → 请用户查实际接线后在**同一轮**内回答，**禁止**代为臆断；仍无法确认 → **终止流程**。

### N3 网卡枚举、数量判定与选择（实时枚举，禁止幽灵设备）
用**脚本 1** 实时枚举本机**物理网卡**（ifIndex / 名称 / 状态 / IPv4 / 前缀长度 / 接收字节数）并输出网卡数量与两个默认候选；该结果即本次 C2 的网卡枚举结果，**禁止重复枚举**，**禁止**把历史 / 缓存 / 已禁用 / 幽灵设备当候选：

```powershell
# 脚本 1：物理网卡枚举 + 数量 + 默认候选（A 场景取 RX 最多 / B 场景取 RX 最少）
# RX 字节数主源为 Get-NetAdapterStatistics；部分网卡（如本机 WLAN）返回空时，
# 回退到 .NET NetworkInterface 统计（按网卡名匹配），二者取其一即可
$nicStats = @{}
foreach ($ni in [System.Net.NetworkInformation.NetworkInterface]::GetAllNetworkInterfaces()) {
    try { $nicStats[$ni.Name] = $ni.GetIPStatistics().BytesReceived } catch { }
}
$nics = Get-NetAdapter -Physical | ForEach-Object {
    $ipObj = Get-NetIPConfiguration -InterfaceIndex $_.ifIndex -ErrorAction SilentlyContinue
    $ip = ''; $plen = 0
    if ($ipObj -and $ipObj.IPv4Address) {
        $first = $ipObj.IPv4Address | Select-Object -First 1
        $ip = $first.IPAddress; $plen = $first.PrefixLength
    }
    $rx = $null
    try { $rx = ($_ | Get-NetAdapterStatistics).ReceivedBytes } catch { }
    if ($null -eq $rx -and $nicStats.ContainsKey($_.Name)) { $rx = $nicStats[$_.Name] }
    [pscustomobject]@{
        ifIndex        = $_.ifIndex
        InterfaceAlias = $_.Name
        Status         = $_.Status
        IPv4           = $ip
        PrefixLength   = $plen
        ReceivedBytes  = $rx
    }
} | Sort-Object ifIndex
$nics | Format-Table ifIndex, InterfaceAlias, Status, IPv4, PrefixLength, ReceivedBytes -AutoSize
"ADAPTER_COUNT=$(@($nics).Count)"
# 候选池 READY：Status 为 Up 或 Disconnected（设备未下载 / 未运行固件时，与之直连的网卡链路即断开，
# 但其 IPv4 配置与 RX 统计仍有效），且必须有 IPv4 与 RX 统计；Disabled / Not Present 等幽灵设备仍排除（C2 禁令）
$ready = @($nics | Where-Object { ($_.Status -eq 'Up' -or $_.Status -eq 'Disconnected') -and $_.IPv4 -and $null -ne $_.ReceivedBytes })
"READY_COUNT=$($ready.Count)"
if ($ready.Count -ge 1) {
    $most  = $ready | Sort-Object ReceivedBytes -Descending | Select-Object -First 1
    $least = $ready | Sort-Object ReceivedBytes | Select-Object -First 1
    "DEFAULT_BY_RX_MOST=$($most.InterfaceAlias) (ifIndex $($most.ifIndex), $($most.IPv4)/$($most.PrefixLength), RX $($most.ReceivedBytes), Status $($most.Status))"
    "DEFAULT_BY_RX_LEAST=$($least.InterfaceAlias) (ifIndex $($least.ifIndex), $($least.IPv4)/$($least.PrefixLength), RX $($least.ReceivedBytes), Status $($least.Status))"
} else {
    "DEFAULT=n/a (no Up/Disconnected physical adapter with IPv4 and RX stats)"
}
```

- **默认候选与用户可选项**（脚本 1 的 `READY` 池）：Status 为 `Up` **或 `Disconnected`**、且有 IPv4 配置与 RX 统计的物理网卡。**设备未下载 / 未运行固件时，与之直连的网卡链路显示断开（`Disconnected`）**，但其 IPv4 配置与 RX 统计仍然有效，**必须**保留为候选——否则双网卡场景会漏掉直连网卡（典型：连接关系 B 下设备侧未跑固件，直连网卡即 `Disconnected`，`READY` 池若只取 `Up` 将只剩一张网卡可选）；`Disabled` / `Not Present` 等幽灵设备仍按 C2 禁令**排除**，无 IPv4 配置或无 RX 统计的网卡**仅供展示**、不入候选池。
- **网卡数量 ≥ 2**（`ADAPTER_COUNT` ≥ 2）→ 由用户选择实体网卡（选择**并入第 2 步 C5 唯一一次交互**，同轮补全；选项 / 正文必须附脚本 1 的实时枚举结果，**禁止**凭空输入或照抄示例），并给出**默认候选**：
  - 连接关系 **A** → 默认**接收字节数最多**的可用物理网卡（经路由器与外界通信的网卡流量最大）；
  - 连接关系 **B** → 默认**接收字节数最少**的可用物理网卡（直连调试网卡流量通常最小）。
  用户改选 → 尊重用户选择；选定后按 C3 / C5 **冻结**，变更必须重新确认。
- **所选网卡链路状态的解释**：连接关系 **A** 下所选网卡若为 `Disconnected` → 说明到路由器 / 交换机的链路不通（网线未接 / 对端未上电 / 端口 down），**必须**提示用户检查物理连接（并入 C5 唯一一次交互，同轮补全），链路恢复后**重新枚举**再继续；连接关系 **B** 下直连网卡为 `Disconnected` 属**正常**（设备未下载 / 未运行固件），按现状继续即可，烧录并运行固件后链路应转 `Up`（可在验证阶段复核）。
- **连接关系 A 且网卡数量 < 2** → 唯一物理网卡即所选，**无需选择**。
- **连接关系 B 且网卡数量 < 2**（`ADAPTER_COUNT` 统计**全部物理网卡**，含 `Disconnected` 链路断开的直连网卡，**禁止**因链路断开而不计数）→ **无可用直连网卡 → 停止网络工具验证**，如实报告并终止本次网络验证流程。
- 所选网卡 IPv4 **不以 192.168 开头**：
  - 连接关系 A → **问询用户是否手动**将该网卡 IP 改设为与设备同网段（由用户在系统设置中手动修改，本技能**禁止**直接修改主机网卡配置）；
  - 连接关系 B → **提示用户手动设置**该网卡 IP（同上，禁止代改）。
  该问询同样**并入 C5 唯一一次交互**（同轮补全）；用户明确表示不改 → 按现状继续，并把该事实写入验证方案与最终报告。
- **仅连接关系 B 追加路由分歧检查**：用脚本 2 判定「所选（直连）网卡」与「**接收字节数最多**的物理网卡」是否在同一网段（脚本 2 的 `ROUTE_DIVERGENCE` 输出）：
  - `ROUTE_DIVERGENCE=1`（**同一网段**）→ 主机对同一网段存在两条路由，访问设备可能走错网卡（**网络路由分歧**）→ 必须问询用户调整其中一块网卡的 IP / 网段（并入 C5 唯一一次交互），调整后**重新判定**；
  - `ROUTE_DIVERGENCE=0`（不同网段）→ 通过。

### N4 设备 IP 网段判定与静态 IP 默认值生成（一律走脚本）
设备默认 IP 与掩码**只能**来自工程代码 / EVT 示例 / 芯片手册（**禁止**臆造；掩码缺省 255.255.255.0 时必须注明该假设来源）。用**脚本 2** 完成判定与候选生成：

```powershell
# 脚本 2：同网段判定 + 路由分歧判定 + 候选静态 IP 生成
# 输入取值一律替换为实时枚举结果 / 工程取值，禁止照抄示例
$NicIp       = '<所选网卡 IPv4>'            # 脚本 1 选定网卡的 IPv4
$NicPrefix   = 24                           # 该网卡前缀长度（脚本 1 的 PrefixLength）
$DevIp       = '<设备默认 IP>'              # 来源：工程代码 / EVT 示例 / 手册
$DevPrefix   = 24                           # 设备掩码前缀（缺省 24 = 255.255.255.0，注明假设来源）
$OtherIp     = '<RX 最多网卡的 IPv4>'       # 仅连接关系 B 的路由分歧检查需要；A 场景留空 ''
$OtherPrefix = 24

function ConvertTo-IPv4UInt32([string]$Ip) {
    $b = [System.Net.IPAddress]::Parse($Ip).GetAddressBytes()
    [Array]::Reverse($b)
    [BitConverter]::ToUInt32($b, 0)
}
function ConvertTo-IPv4String([uint32]$V) {
    $b = [BitConverter]::GetBytes([uint32]$V)
    [Array]::Reverse($b)
    ([System.Net.IPAddress]::new($b)).IPAddressToString
}
function Get-SubnetMaskUInt32([int]$PrefixLength) {
    if ($PrefixLength -le 0)  { return [uint32]0 }
    if ($PrefixLength -ge 32) { return [uint32]4294967295 }
    [uint32](4294967295L - ((1L -shl (32 - $PrefixLength)) - 1))
}

# ---- 同网段判定（设备 IP & 掩码 vs 所选网卡 IP & 掩码）----
$mask   = Get-SubnetMaskUInt32 $NicPrefix
$nicNet = [uint32]((ConvertTo-IPv4UInt32 $NicIp) -band $mask)
$devNet = [uint32]((ConvertTo-IPv4UInt32 $DevIp) -band $mask)
if ($nicNet -eq $devNet) {
    if ($NicIp -eq $DevIp) { 'DEV_IP=CONFLICT' } else { 'DEV_IP=SAME_SUBNET_KEEP' }
} else {
    'DEV_IP=DIFF_SUBNET'
}

# ---- 路由分歧判定（仅连接关系 B：直连网卡 vs RX 最多网卡）----
if ($OtherIp -ne '') {
    $oNet = [uint32]((ConvertTo-IPv4UInt32 $OtherIp) -band (Get-SubnetMaskUInt32 $OtherPrefix))
    if ($oNet -eq $nicNet) { 'ROUTE_DIVERGENCE=1' } else { 'ROUTE_DIVERGENCE=0' }
}

# ---- 候选静态 IP：所选网卡同网段、网卡 IP + 1 起、跳过广播地址 ----
$nicV = ConvertTo-IPv4UInt32 $NicIp
$bcV  = [uint32]($nicNet -bor ($mask -bxor [uint32]4294967295))
$cur  = [uint32]($nicV + 1)
if ($cur -ge $bcV) { throw 'NO_FREE_ADDRESS: 该网段网卡 IP 之后已无可用地址' }
"CANDIDATE_STATIC_IP=$(ConvertTo-IPv4String $cur) / $NicPrefix"
```

- 脚本 2 输出 `DEV_IP=` 三种取值，处理规则：
  - `DIFF_SUBNET`（设备与所选网卡**不同网段**）→ 生成候选静态 IP；
  - `CONFLICT`（同网段但设备 IP 与网卡 IP **相同**）→ 生成候选静态 IP；
  - `SAME_SUBNET_KEEP`（同网段且 IP 不同）→ **保持设备默认 IP**，无需生成。
- 候选生成规则（脚本 2 的 `CANDIDATE_STATIC_IP`）：在所选网卡同网段内取**网卡 IP + 1** 起的下一个可用地址（跳过广播地址；`NO_FREE_ADDRESS` 时如实报告并终止）；该值仅作为静态 IP 的**默认值**。
- 生成的 IP **必须写入验证方案**（注明来源为脚本 2 输出），经第 2 步 **C5 唯一一次弹框**确认后，作为第 4 步代码生成中固件**静态 IP 的取值**（由模型把该值写入固件代码的静态 IP 宏 / 变量）；**禁止**未经确认直接改固件。
- 连接关系 B 时，设备静态 IP 必须落在**直连（所选）网卡**的网段内（脚本 2 以 `$NicIp` 为基准生成即满足）。

### N5 结论冻结与转交
N1–N4 结论（协议栈有无 / 连接关系 A 或 B / 选定网卡 ifIndex + 名称 + IP / 设备 IP 决议：保持默认或改为候选值（含掩码）/ 路由分歧处理结果）并入**验证方案与硬件连接表**，按 C3 / C5 **冻结**；第 5 步转交 `mrs-external-tools` 时必须一并带上，其按 **C4 / C5** 复用，**禁止**重复执行本节任何检查。

## 工作流程

### 第 1 步：规划全局方案（代码设计 + 验证方式）
先阅读工程源码与用户需求，记录并分析：
- 目标功能与改动点；
- 现有外设 / 驱动 / 引脚占用情况；
- 调试接口（COM / USB / BLE / 以太网）与固件打印行为（仅启动打印一次 / 固定次数 / 周期性 / 无）；
- 是否需要复位 / 烧录（下载）后才能验证，以及预计执行时长；**需要下载时**记录**下载方式 = WCH-Link（外置 / 板载）**，并把「**经 WCH-Link 下载 → 复位 → 观察**」与**下载成功判据**（下载工具报告成功 / 校验通过）写入验证方案；
- 是否存在**网络接口 / 以太网模块**，以及固件是否包含**网络协议栈（TCP / UDP）**（供 **N1** 判定）；含协议栈时还须记录设备**默认 IP / 掩码及其来源**（工程代码 / EVT 示例 / 手册）。

据此产出**验证方案草案**，**必须同时包含**两部分：
1. **代码设计**：要新增 / 修改哪些文件与函数、外设如何初始化、**引脚如何分配**、数据协议 / 打印格式；
2. **验证方式**：用哪个工具、验证哪些现象、**明确的通过 / 不通过判据**、预计时长、需要的外部硬件。

**规划前必须真正查阅依据（强制）**：与外设 / 引脚 / **物理口丝印** / 板版本相关的一切内容，**必须实际查阅评估板说明书 / 原理图**（或工程原理图、芯片数据手册）**之后**才能出规划，并据此建立「**物理口丝印 ↔ MCU 引脚**」对应表作为硬件连接表依据；硬件连接表**必须注明依据来源**（见 **C3**「数据来源（强制）」）。**禁止**未查阅就先出规划、**禁止**凭记忆 / 凭示例 / 凭推测臆造引脚与丝印；查不到 → **如实说明并列为不确定项**，**禁止**编造（**丝印例外**：丝印确实查不到时按 C3「丝印前置门槛」例外处理——该连接项**不写**丝印子节点，**表内表外均不提**）。**板版本不明确时按 C3「板版本不明→全列」处理**，直接列出所有板版本，**不得**转为向用户追问。

**方案必须可执行、可判定**：每个验证点都要有明确判据；**禁止**使用「看看是否正常」「观察一下」这类无法判定的描述。

### 第 2 步：输出「验证方案 + 硬件连接表」，并**一次性弹框**确认（★ 全程唯一一次交互）
**顺序（强制，禁止颠倒）：先输出 → 再弹框；且全程只弹这一次。**
- **① 先输出**（弹框前**必须**把下列内容**完整写出**）：
  - **验证方案全文**（要素一项不漏，见第 1 步的「代码设计 + 验证方式」）；
  - **硬件连接表**（按 **C3** 规范：**全局约定 + 文字说明 + 图示意**，**覆盖全部连接项、一项不漏**）；
  - **网络检测结论**（若触发 N1–N5）：**N5 的全部结论**（协议栈有无 / 连接关系、选定网卡、设备 IP 决议与候选静态 IP、路由分歧处理结果）。
- **② 再弹框**（**二合一**，本次即 **C5** 的唯一一次交互）：
  - **验证方案**：接受 / 自行输入（**解析后缺项必须在同一轮补齐再确认**）/ 不接受（→ **立即终止**）；
  - **硬件连接已就绪确认**：是否已按**硬件连接表全文**逐条就绪（含**表首全局约定（共地 / 供电 / 电平 / 接线顺序）、文字说明逐条连接项与图示意**）；**弹框正文必须逐行照录硬件连接表全文**（全局约定 + 文字说明 + 图示意，**禁止**缩写 / 省略 / 合并 / 只写摘要）；

**禁止**：先弹框后输出；弹框中不给 / 不引用已输出的方案与接线摘要；只输出不弹框；只弹框不输出；**拆成两次或跨轮询问**；跳过弹框直接生成代码；把「用户没有反对」当作同意；未确认就进入第 3 步。

**同轮补全例外**：发起确认前若有关键配置无法确定，**允许在同一轮内先问配置 → 拿到答案后立即补全接线指引并在本轮确认**；**禁止**先问配置、隔一轮再问接线（那会变成两次交互）。**网络检测的连接关系问询（N2）、网卡选择与非 192.168 问询（N3）即按本例外执行**。

确认后记录的**最终验证方案 + 硬件连接表**是后续代码生成与验证的**唯一依据**，并**立即冻结**（C3 / C5）。

### 第 3 步：冻结硬件连接表并按方案执行（**不再与用户交互**）
第 2 步的**同一次弹框**已同时完成方案确认与硬件连接确认，本步**不得**再次弹框：
- 按第 2 步确认的**硬件连接表**固化并**冻结**（引脚 / 外设 / 对端设备不得变更；确需变更 → 重新走一次第 2 步，即**新的一次交互**）；
- 硬件连接表内容**必须**与方案**逐项一致**（严格执行 **C3** 规范）；
- 网络接口 / 以太网模块场景的网卡枚举与选择已在第 1 / 2 步按**网络检测 N2 / N3** 完成（其枚举结果即本次 C2 的网卡枚举结果，**禁止重复枚举**），其结论（N5）随硬件连接表**一并冻结**；
- 该硬件连接表是第 4 步代码生成的**引脚依据**：代码中的引脚分配**必须**与之一致。

若发现设备 / 接线与表**不一致** → **不询问**：**必须**如实报告并按 **C2 / C4** 处理（无法确认即终止；确需变更则重新走一次第 2 步）。

### 第 4 步：新建 / 打开工程并执行代码生成（**此前禁止建工程**）
**先规划、先确认，才能建工程（强制）**：**必须**在「**验证方案确认 + 硬件连接确认**」（第 2 步同一次弹框）完成之后，才允许**实际新建工程 / 打开或修改既有工程**并开始写代码；**禁止**先新建工程、先动手写代码，再补方案与硬件连接确认；**禁止**以「先把工程搭起来再规划」为由绕过本门禁。

只有在「**验证方案已确认**」且「**硬件连接已就绪确认通过**」（第 2 步同一次弹框）之后，才执行代码生成：
- 代码**必须**与已确认的代码设计、接口与**引脚分配一致**；
- 若 N4 生成并经确认了**候选静态 IP**，**必须**把该值写入固件代码的静态 IP 宏 / 变量（与已确认方案一致）；
- **禁止**擅自更改已确认的引脚 / 接口 / 协议；确需变更 → 回到第 2 / 3 步**重新确认**后再改。

### 第 5 步：验证阶段调用 `mrs-external-tools`
代码生成完成、进入验证阶段时，**必须**调用技能 `mrs-external-tools`，由它按自身红线与约束完成工具查询 / 缓存 / 安装 / 调用 / 清理（含「先依参数手册判定实例数、单实例够用就只开一个、不够才多实例」的红线）。
转交时**必须**带上本次已确认的**验证方案与硬件连接表**（含实时枚举到的实际设备、**网络检测 N5 结论**）：`mrs-external-tools` 据此按 **C4 / C5** **必须跳过** C1–C3、**不得再向用户发起任何交互**（**禁止**要求用户重复确认方案 / 设备连接 / 接线），也**禁止**重复执行网络检测 N1–N5；若其执行时发现设备与硬件连接表不一致，**必须**回报并回到本技能重新确认。
本技能**禁止**直接启动工具，**禁止**臆造工具名 / `toolID` / 路径 / 参数，**禁止**另写脚本替代其两个通用脚本。
验证时按第 2 步确认的**判据**逐项核对，并按 `mrs-external-tools` 的报告规则输出结论。

**验证阶段无法继续时的终止（多轮验证中判定）**
- **每轮核对（只读）**：每轮验证前后核对「本轮所需设备是否仍在册且与**已确认的硬件连接表**一致」与「本轮判据是否仍可观测」。**禁止**因一次超时 / 一次无响应就判不可继续，**禁止**把没取到数据当作判据不通过。
- **判定与终止**：若确认**按当前验证方案与硬件连接表已无法继续验证**（设备实时枚举不到 / 与表不一致且无法恢复、工具手册不支持方案所需的多目标、方案与表互相矛盾、判据无法观测）→ **立即**停止发起新轮次（不再发新命令、不再复位 / 下载、不再追加测试轮），**终止本次流程**。
- **禁止降级**：终止时**禁止**改用直连串口 / TCP、其他软件、自写脚本或人工主观判断顶替，**禁止**擅自修改已确认的验证方案与硬件连接表。
- **收尾与输出**：按 `mrs-external-tools` 既有收尾规则结束实例、清理；并**直接向用户输出**终止信息——终止的轮次与位置、原因与实测证据、是**验证方案**还是**硬件连接表**的哪一项不适配、已得出的结论、**因终止无法判定的项**（**禁止**把未验证写成通过 / 不通过）、下一步建议（恢复接线后按原方案重跑 / 变更方案与表后重新确认 / 更换工具或仪器）。**禁止**弹框追问；展示遵守第 10 条（**禁止**显示 `toolID`，**禁止**提及临时文件）。
- 与第 270 行不冲突：设备 / 接线能恢复到与表一致即继续按原方案验证，恢复不了即属本条「无法继续」→ **终止**。

## 强制约束（MUST / 禁止）
1. **设备枚举必须实时、真实可用（禁止幽灵设备）**：**必须**按**共用检查逻辑 C2** 执行——用 `bash`（Windows 用 PowerShell）**实时枚举**并与当前实际设备实例交叉印证（串口 `Get-PnpDevice -Class Ports -Status OK` / `Get-CimInstance Win32_SerialPort` 与 `[System.IO.Ports.SerialPort]::GetPortNames()` 相互印证；USB `Get-PnpDevice -Class USB -Status OK`；网卡 `Get-NetAdapter | Where-Object Status -eq 'Up'`；蓝牙须为当前实际存在且可用）；**禁止**历史记录 / 缓存 / 注册表残留 / 已拔出 / 已移除 / 已禁用 / 隐藏设备；为空或**无法确认** → **禁止**使用，如实报告并终止或请用户重新连接 / 确认。
2. **硬件连接检查必须覆盖全部连接项、精确到引脚、符合硬件连接表规范，且与已确认方案一致**：**必须**按**共用检查逻辑 C3** 执行——硬件连接表由三部分组成、**顺序固定**：**① 全局约定**（置于**表首**、只写一次：共地 / 供电来源 / 电平匹配 / 建议接线顺序）；**② 文字说明**（**主行 + 一层子节点**：主行只写 线号 + 勾选框 + 引脚号 + 引脚名 + 方向 + 一句话语义；**丝印子节点必填**——物理丝印名 + 针位，多板版本并列全列（**唯一例外**：依据文档确实查不到丝印时按 C3「丝印前置门槛」例外处理——该连接项**不写**丝印子节点，**表内表外均不提**），依据与丝印同行，**丝印子节点必须为缩进一层的子列表项（行首 `- └ `、渲染可见缩进）、主行内不得出现 `丝印` / `依据` / `端点` 字样**；**丝印名 / 引脚号等重点标识一律用行内代码（反引号包裹）以深色背景突出显示；线号除外——线号统一写成 `[W1]线`，整段不加反引号、不显示深色背景**）；**③ 图示意**（纯 ASCII、三段式 `MCU 侧标注 →（线号 + 方向）→ 对端侧标注`、**图首独占一行表头标注 `MCU侧`（目标板 MCU 侧）与对端侧实际身份**、**线上只标线号与方向且不得出现功能描述**、**MCU 侧只写引脚号 + 引脚名（不写丝印 / 针位）**、必须含 GND 线、图内标注一律 ASCII、每行 ≤ 72 字符），每张卡片按「卡片标题 → 文字说明 → 图示意」排列；**取消「需要接线 / 无需接线」分类**——引脚跳线、板载 USB 口、板载调试口、网口、内置无线**一律同权逐条列出**（**禁止**漏项 / 合并 / 省略）；**数据来源与板版本处理按 C3「数据来源（强制）」「板版本不明→全列」执行**；用户**手动确认**，且与**最新确认的方案逐项一致**（**禁止**方案外的器件 / 引脚，**禁止**遗漏）；确认弹框**必须自包含**（全局约定 + 文字说明 + 图示意**逐行照录**进弹框正文，**禁止**缩写 / 省略 / 合并 / 只写摘要）且**能合并的必须合并**；**确认后引脚 / 外设 / 对端冻结**，变更**必须**重新确认。该硬件连接表是代码生成的**引脚依据**（第 4 步），代码引脚分配**必须**与之一致。
3. **一次交互（弹框前置且唯一）**：验证方案确认 + **硬件连接已就绪确认**（含表首全局约定、文字说明逐条连接项与图示意全文）**必须合并为同一次弹框**，并在生成代码**之前**完成；**全程只允许这一次用户交互**（见 **C5**）；**禁止**拆成两次 / 跨轮追问、**禁止**零散反复弹出、**禁止**临时追加未合并的确认。
4. **顺序不可颠倒（先确认后建工程）**：规划 → 验证方案确认 + 硬件连接确认（同一次弹框） → **新建 / 打开工程** → 代码生成 → 工具验证；**禁止**在方案与硬件连接确认之前**新建工程**或写代码；**禁止**先生成代码再补方案 / 接线；用户中途改变要求时，也**必须**先补齐确认再继续。
5. **用户未确认一律不得继续**：用户**拒绝**方案、或**未完成**确认时，**必须**终止流程；**禁止**代替用户默认同意，**禁止**带着未确认的方案 / 接线生成代码或调用工具。
6. **方案必须可执行、可判定**：每个验证点都要有明确的通过 / 不通过判据；**禁止**含糊、无法判定的验证描述。
7. **确认结果是唯一依据**：确认后的验证方案与硬件连接表是后续代码生成与验证的唯一依据；任何变更**必须**重新确认，**禁止**擅自改动。
8. **禁止臆造**：**禁止**臆造设备标识（串口号 / VID / PID）、引脚名、工具名 / `toolID` / 路径 / 参数；所有取值**只能**来自实时枚举结果、工程配置 / 原理图、`mrs-external-tools` 的工具缓存与手册，或用户输入；其中**评估板说明书 / 原理图中的连接器丝印与引脚对应关系**属合法来源，据此标注**不构成臆造**。
9. **工具调用一律走 `mrs-external-tools`**：**禁止**自行启动工具、**禁止**另写脚本替代其通用脚本、**禁止**绕过其安装 / 参数 / 清理规则（见该技能第 2 / 18 / 21 / 26 条）。
10. **报告边界**：最终报告只陈述「确认后的验证方案、**硬件连接表确认结果**、验证结论与必要建议」；展示工具信息时遵守 `mrs-external-tools` 的展示禁令（**禁止**显示 `toolID`），临时文件相关内容同样**禁止**出现在报告中。
11. **网络检测一律走 PowerShell 脚本（N1–N5）**：工程含网络接口 / 以太网模块时，**必须**按「网络检测 N1–N5」执行——N1 协议栈判定决定是否做网络工具验证（无协议栈仅收发以太网帧 → 不需要网络工具验证）；连接关系问询（N2）、网卡选择与非 192.168 问询（N3）**必须并入 C5 唯一一次交互**（同轮补全，禁止单独弹框；默认候选：A 场景取**接收字节数最多**、B 场景取**接收字节数最少**的候选物理网卡，**候选池含 `Up` 与 `Disconnected` 链路断开的网卡**——设备未下载 / 未运行固件时直连网卡即断开，**禁止**因链路断开而将其排除出候选）；同网段判定、候选静态 IP 生成（网卡 IP + 1 起）、路由分歧判定**必须**用 N3 / N4 的 PowerShell 脚本完成，**禁止**模型心算，**禁止**使用 Python；设备默认 IP / 掩码只能来自工程代码 / EVT 示例 / 手册；**禁止**直接修改主机网卡配置（只问询 / 提示用户手动设置）；连接关系 B 且网卡数量 < 2 → **停止网络工具验证**；候选静态 IP 未经确认**禁止**写入固件。

## 与其他技能的关系
- **共用检查逻辑**：两个技能各自收录**同一份 C1–C4**（**逐字一致**）；**任一技能执行过，另一技能必须跳过、不得重复检查**（C4）。
- **本技能**（`mrs-prepare-verify`）：**生成前**的规划与一次性双重确认（验证方案 + **硬件连接表**合并为 C5 唯一一次交互），是进入代码生成的门禁。
- **`mrs-external-tools`**：**验证阶段**的实际执行者（工具查询 / 缓存 / 安装 / 调用 / 清理，含单 / 多实例红线）。
- **衔接点**：第 5 步**必须**显式转交，且带上已确认的**验证方案与硬件连接表**，使 `mrs-external-tools` 按 **C4 / C5 跳过** C1–C3、**不再发起任何交互**；**禁止**跳过它直接调用工具。
- **网络检测（N1–N5）**：仅本技能收录与执行；结论按 N5 冻结并随验证方案转交，`mrs-external-tools` 按 C4 / C5 直接复用，**禁止**重复检测。
