# MRS 工具

## 目标
根据用户的分析或验证目标，选择最合适的 MRS 工具，并**严格按顺序**执行：
工程代码分析 → **输出「验证方案 + 硬件连接表」并一次性弹框确认（`mrs-prepare-verify` 已做过则跳过）** → 前置检查与场景检查 → 查询并缓存工具列表 → 按需安装 → **依参数手册判定实例数** → 调用 → 清理。
（若本次流程已由 `mrs-prepare-verify` 执行过共用检查逻辑 C1–C3 及其 **C5 唯一一次交互**，则**必须跳过**重复的前置 / 场景检查与全部弹框，直接进入第 4 步——见 **C4 / C5**。）

> ## ⚠ 最高优先级红线：实例数必须先依参数手册判定
> **本条优先级最高，凌驾并优先于其余全部步骤与约束；冲突一律以本条为准，任何理由（方便、排障、重试、超时、多轮测试、脚本写法、用户催促等）都不得放宽。**
> - **实例数判定（读完手册之后、启动工具之前；属实际执行验证阶段）**：结合第 1 步代码分析、第 3 步实时设备枚举与**第 6 步实际读到的** `manual_location` 参数手册，**逐软件**判断「单个实例能否满足全部需求」——能否同时覆盖所需设备 / 通道 / 会话 / 并发收发；手册是否写明该软件一次只能打开一个串口 / 设备 / 连接 / 会话。**规划方案阶段（第 1–3 步）不查手册、只输出流程**，最终判定在**实际执行验证阶段（第 6 步）**完成。
> - **够用 → 只开一个**：由 `mrs_pipe_host.ps1` 以 `/pipe` 完成唯一一次启动并**全程常驻**；设备枚举 / 多轮取数 / 多条命令 / 反复测试全部发给同一进程。
> - **不够用（手册明确一实例无法覆盖多目标）→ 允许多实例**：每个实例**各自只启动一次、各自全程常驻**，用 `-Instance <实例名>`（仅字母 / 数字 / `-` / `_`）区分，各实例文件按实例名分开，分别用 `mrs_pipe_host.ps1` / `mrs_pipe_send.ps1` 通信（`-List` 列实例，`-Instance <实例名> -Stop` 结束指定实例）。
> - **共同红线**：任何实例都**禁止同流程内重复启动**（禁止中途重启 / 再开同实例 / 失败重启重试 / 关掉重开）；单实例够用时**禁止**多开。
> - **两个例外**：① 实例**非正常退出**（崩溃 / 被占用 / 报错终止）→ 可结束流程、清理后**重走一次完整流程**（先收后发时序见第 22 条）；② 被**安全软件拦杀**（进程启动即退、就绪标记不出现、`phase=error` 或停在 `starting` / `tool-started`）→ 清理该实例状态后**就地重试一次**（host 与发送进程各限一次），仍失败即**终止并提醒用户**（第 32 条）。两例外均**不得**当作常规排障重试。
> - 完整表述见强制约束**第 1 / 32 条**。

**规划与调用总则**：**规划方案阶段（第 1–3 步，含输出并确认验证方案）不需要、也不得使用查询工具**——本阶段**只输出流程**（要做哪些检查、外部硬件怎么连、验证什么、判据是什么、按什么顺序执行），**禁止**调用 `ide-get-external-toolList-description`、**禁止**查询 / 安装工具、**禁止**读取 `manual_location` 手册。**只有进入实际执行验证阶段（第 4 步起）才使用查询工具**：此时**必须**先 `ide-get-external-toolList-description` 查询并缓存工具列表与手册（第 8 / 17 条；查询失败按第 33 条**重试一次**，仍失败即**终止并提醒用户**），再选择 / 安装 / 读取 `manual_location` 并**判定实例数**（第 6 步），**禁止**臆造工具 / 参数。工具**未安装不等于不可用**：`hasInstalled: false` 时**必须**按第 6 步安装，**禁止**因此放弃或改用替代方案（第 18 条）。**默认工具功能正常**，按 `manual_location` 直接调用，**禁止**任何前置探测 / 试运行（第 19 条）。调用方式固定为**随技能分发的两个通用脚本**，只从本技能目录定位并直接调用，**禁止**动态生成 / 改写 / 用替代脚本（第 7 步、第 2 / 26 条）。

## 使用场景判断（不满足则不进行）
按下方**共用检查逻辑 C1** 判定（① 会用工具验证 + ② Windows 平台）。本技能**不受**「用户需求须为生成代码类」限制——该条仅属 `mrs-prepare-verify`。
**去重（强制）**：若本次流程**已由 `mrs-prepare-verify` 执行过 C1–C3**，则**必须跳过**这些检查（**禁止**重复弹框、**禁止**重复枚举），直接进入第 4 步，按 **C4** 处理；其 **C5 唯一一次交互**若已完成，本技能**不得再向用户发起任何弹框或询问**（见 C5「已确认即不重复」）。

本技能说明如何在 Windows 平台通过 MRS IDE 查询并缓存、按需安装并一次性调用 BLE、USB、COM、以太网等调试工具。典型场景：查询 USB / BLE / 串口调试工具集支持列表；按软件名自动定位本机可执行文件路径（必要时在线下载、解压安装、版本更新）；供自动化脚本或 AI 助手直接启动 WCH 调试工具（串口助手、USB 分析仪、BLE 调试工具）。

## 共用检查逻辑 C1–C4（场景检查 + 硬件连接检查）
> 本节在 `mrs-prepare-verify` 与 `mrs-external-tools` 中**逐字一致**，是两者**唯一**的检查依据；**任一技能执行过即视为已完成，另一技能必须跳过、不得重复检查**（见 C4）。

**C1 场景检查（是否进入工具验证流程）**
- ① 本次流程**确实会使用**工具（USB / 串口 / 蓝牙 / 以太网等）验证代码 / 硬件效果。
- ② 平台须为 **Windows**；非 Windows → 说明平台限制，**禁止**尝试调用或安装。
- ③ 暂时**无法判断** ① → 并入流程开始的**同一次合并询问**确认，**禁止**反复弹框。
- 判定：①+② 满足 → 进入 C2 / C3；① 不满足 → **不做设备验证**（与设备验证无关的工具查询 / 安装等请求可继续）；② 不满足 → **终止**并说明限制。**默认判定（强制）**：请求为**纯编译 / 无外设交互**（不涉及 USB / 串口 / 蓝牙 / 以太网等外部设备）时，**直接归为「不做设备验证」**，**不得**据此弹框或输出硬件连接表。

**C2 设备枚举检查（必须实时、真实可用）**
- **必须**用 `bash`（Windows 用 PowerShell）**实时枚举**并与当前实际设备实例交叉印证：串口 `Get-PnpDevice -Class Ports -Status OK` / `Get-CimInstance Win32_SerialPort` 与 `[System.IO.Ports.SerialPort]::GetPortNames()` 相互印证；USB `Get-PnpDevice -Class USB -Status OK`；网卡 `Get-NetAdapter | Where-Object Status -eq 'Up'`；蓝牙须为当前实际存在且可用的控制器：用 `Get-PnpDevice -Class Bluetooth -Status OK` 实时枚举（可用 `Get-CimInstance Win32_PnPEntity` 交叉印证）并结合蓝牙服务（`Get-Service bthserv, BTAGService`）状态判定，**禁止**把已禁用 / 已拔出 / 隐藏的幽灵适配器当作可用。
- **禁止**把**历史记录 / 缓存 / 注册表残留 / 已拔出 / 已移除 / 已禁用 / 隐藏设备**等**幽灵设备**当作可用设备；候选列表**必须**来自实际枚举结果，格式 `<实际标识> (<实际设备描述>)`，**禁止**凭空输入或照抄示例。
- 枚举结果为空或**无法确认**某设备当前真实存在 → **禁止**使用该设备，**必须**如实报告并终止，或请用户重新连接 / 确认。
- **需要烧录 / 下载时**（含「必须先下载才能验证」）：**必须**实时枚举一次 **WCH-Link 下载器**（外置 WCH-Link 与评估板**板载 WCH-Link** 均按 WCH-Link 处理；用 `Get-PnpDevice -PresentOnly -Status OK` 匹配设备描述含 `WCH-Link` 者，并与 `Get-PnpDevice -Class USB -Status OK` 交叉印证）；结果**只用于 C5 的 WCH-Link 确认**，**不写入硬件连接表、不逐引脚展开**；枚举为空 / **无法确认** → **禁止**下载，如实报告并终止（**禁止**用历史记录 / 幽灵调试器顶替）。

**C3 硬件连接检查（硬件连接表规范：全局约定 + 文字说明 + 图示意）**

- **表的定位（强制）**：输出物统一称**硬件连接表**，它**必须覆盖本次验证用到的全部硬件连接**。**取消「需要接线 / 无需接线」分类**：**凡是必须建立的物理连接一律同权、同格式、逐条列出**——引脚跳线 / 转接 / 外接模块与**板载 USB 口 / 板载调试口 / 网口 / 内置无线等全部同列**；**禁止**把板载口 / 网口 / 内置模块当作「不用接线」而漏项 / 合并 / 省略，**禁止**只列跳线项。
- **结构（三部分，顺序固定，缺一不可）：① 全局约定 → ② 文字说明 → ③ 图示意**（**分工**：图 = 电气连接、**与板版本无关**；文字 = 物理落点、**随评估板版本变**——丝印 / 针位 / 板版本 / 依据）：
  - **① 全局约定**：置于**表首**，全表**只写一次**，任何一项都不得省略——**共地**（`GND ↔ GND`）；**供电来源**（MCU 与对端各由谁供电）；**电平匹配**（3.3V / 5V、是否需电平转换）；**建议接线顺序（先共地 → 再信号 → 最后电源）**。
  - **② 文字说明**：**一条 = 一个连接项**，分**主行 + 子节点**两层（**只允许一层子节点，不做三级缩进**）：**主行只写四样、必须一行、尽量短**——`□ [<线号>]线 <MCU 侧引脚号> <引脚名> → <对端口 / 引脚号> <引脚名>（方向）—— <一句话语义>`，**禁止**在主行堆丝印 / 依据 / 参数 / 长解释；**线号一律写成 `[W1]线`（方括号包裹线号 + 其后加「线」字）；线号整段不加反引号（避免深色背景），其余关键标识仍用反引号高亮**；MCU 侧引脚号为空（如 `GND`）时同样写 `□ [W5]线 GND →…`，**禁止** `□ W5 GND …` 这类线号与引脚名连读的写法；**子节点必须是缩进一层的 Markdown 子列表项**（父行 `- □ [W1]线 …`，子行 `  - └ 丝印：…`）——**仅用前导空格缩进会被 Markdown 折叠为主行同级（顶格），判为错误**——`  - └ 丝印：<板版本> <物理丝印名 + 针位>…（依据：<文档 / 页>）`，**丝印落点必填**（唯一例外：按本节「丝印前置门槛」判定依据文档**确实查不到**时，该连接项**不写**丝印子节点）、多板版本**并列全列**，USB 场景另可加 `  - └ 端点：<地址 / 方向 / 类型 / 包长>`；**层级红线（强制、可机检）**：**层级（缩进）是强制结构、不是可选项**，丝印 / 依据 / 端点信息**一律不得出现在主行**——**主行内出现 `丝印`、`依据`、`端点` 字样即判定层级放错**，必须下沉为缩进子节点；**禁止**子节点与主行同列、**禁止**写进主行末尾、**禁止**用 `；` / `,` 并进主行；**简洁红线**：语义**限一句话**、主行 **≤ 80 字符**（超长即下沉为子节点）；与图中线号**一一对应、同名同数**；板载 USB 口 / 网口 / 内置无线等**同样按此格式写成正常连接项**，**禁止**写成「无需接线」这类豁免描述。
  - **② 正 / 反例（层级示范，实际输出必须照此两层层级）**：
    - ✓ 正确（主行顶格 + 子节点为缩进一层的子列表项，渲染可见缩进）：
      ```
      - □ [W1]线 `PA2` `USART2_TX` → 对端 CH340 `RXD`（输出）—— 目标板串口发往 PC
        - └ 丝印：`CH32V307EVT`=`P6`/`P7`/`P9`（依据：评估板说明书「MCU I/O 口」）
      ```
    - ✗ 错误①（丝印与主行同级、缺缩进与 `└ `）：
      ```
      - □ [W1]线 `PA2` `USART2_TX` → 对端 CH340 `RXD`（输出）—— 目标板串口发往 PC
        丝印：`CH32V307EVT`=…（依据：…）
      ```
    - ✗ 错误②（丝印并进主行同一行）：
      ```
      - □ [W1]线 … —— 目标板串口发往 PC  丝印：…（依据：…）
      ```
    - ✗ 错误③（子节点仅用前导空格、无列表标记 → Markdown 折叠为顶格）：
      ```
      - □ [W1]线 `PA2` `USART2_TX` → 对端 CH340 `RXD`（输出）—— 目标板串口发往 PC
        └ 丝印：`CH32V307EVT`=…（依据：…）
      ```
  - **② 重点突出（强制）**：文字说明中所有**关键标识**——**物理丝印名（丝印号）**、**引脚号**（MCU 侧与对端侧均含）、**子节点里的丝印名与依据**——**一律用半角反引号成对包裹为行内代码**，借助其渲染出的**深色背景**突出显示（示例：`P6`、`PA9`）；**线号除外**——线号统一以 `[W1]线` 形式写出，**整段不加反引号、不显示深色背景**，方括号 `[ ]` 与「线」字保持纯文本；**禁止**仅靠加粗替代、也**禁止**不加任何强调地埋在普通文本里（线号不受此限）；同一标识在**主行、子节点与图示意**中**必须一致**（图示意为纯 ASCII，**不加反引号**，只保证标识字符相同）。
  - **③ 图示意**：纯 ASCII（只用 `< > - | +` 与半角空格）画出**全部连接项**，且**全部连接项合并为同一张连续图**（**整表唯一图**：全表**只输出这一张图**，任何情况下**不得**出现第二张图 / 分图 / 每卡一图）（逐行排列，**禁止**按对端设备 / 子系统 / 接口分段，**禁止**用空行、小标题或分块把一张图拆成多段）；固定三段式 `MCU 侧标注 →（线号 + 方向）→ 对端侧标注`；**图首必须独占一行标注两端身份**——左列表头固定写 `MCU侧`（即目标板 MCU 侧）、右列表头写 `对端`（**对端唯一**时写**该对端实际身份**，如 `CH340` / `PC` / `RJ45`；**对端不唯一**时表头固定写 `对端`，且**每行右侧**须写 `<对端设备> <引脚名>` 以区分），两表头分别与下方左、右列左对齐（示例首行：`MCU侧                    对端(CH340)`）；该表头是**整张图唯一的表头**，**不是**「小标题」、不得据此把图拆段；**MCU 侧只写 `<引脚号> <引脚名>`（引脚号为空时只写引脚名，如 `GND`），不写丝印 / 针位**——丝印随评估板版本变，统一放 ② 文字说明；**线上只标线号与方向**（如 `--W1-->` / `<--W2--`），**禁止**在图上出现任何**功能描述**（发送 / 接收 / 交叉 / 共地 / 依据 / 参数等一律不进图）；**必须含 GND 线**（线上不写「共地」字样）；**图内标注一律 ASCII**；**每行 ≤ 72 字符**；**通信参数 / 依据来源不进图**。
- **卡片标题（每张卡片一行，属文字说明的标题）**：**接口 / 对端设备 + 通信参数**；**该行必须整行加粗**（Markdown `**…**` 包裹）。
- **卡片内顺序（强制）**：每张卡片**只**按「**卡片标题 → 文字说明**」排列，**卡片内不得出现任何图**；**整张硬件连接表全程只允许存在一张图**（即 ③ 图示意，**唯一图**），该图**必须置于全部卡片文字之后、统一输出一次**，**禁止**每张卡片各画一张图、**禁止**图与卡片文字交错、**禁止**出现第二张图 / 重复图 / 分图。
- **板版本不明→全列（禁止询问）**：板版本不明确时**禁止询问用户**，必须依据评估板说明书 / 原理图**直接列出所有已知板版本**（如 R1 / R2 / R3、旧版 CH32V307EVT、CH32V303EVT）对该接口的丝印名与 MCU 引脚对应，在硬件连接表中**并列完整呈现**，由用户自行对号入座；仅当版本已明确时才只列对应版本。
- **数据来源（强制）**：外设 / 引脚 / **物理口丝印** / 板版本等信息**必须**来自**实际查阅过**的**评估板说明书 / 原理图**（或工程原理图、芯片数据手册），并在硬件连接表中**注明依据来源**（哪份文档 / 哪个文件、哪一页 / 哪个网络名）；**禁止**未查阅就先规划或先写硬件连接表，**禁止**凭记忆 / 凭示例 / 凭推测臆造；查不到 → **如实说明并列为不确定项**，**禁止**编造（**丝印例外**：丝印确实查不到时按本节「丝印前置门槛」例外处理——该连接项**不写**丝印子节点，且**表内表外均不提**、不留任何「未查到 / 不确定」痕迹）。
- **禁止模糊表述**：「连接到串口 / 接到电脑 / 接上调试器」这类写法**一律禁止**；板载口（USB / 网口 / 调试口等）**必须写明物理丝印名**（如 `P6` / `P7` /「网口」）并给出其对应 MCU 引脚，**禁止只写「板载口」**。
- **串口（UART）人工接线必须「收发引脚逐一对应」**：**必须**逐条列出 `TX（引脚号 + 引脚名）↔ 对端 RX（引脚号 + 引脚名）`、`RX（引脚号 + 引脚名）↔ 对端 TX（引脚号 + 引脚名）`（**收发必须交叉**）、`GND ↔ GND`；有流控时补 `RTS ↔ CTS` / `DTR ↔ DSR`，RS-485 补 `A ↔ A` / `B ↔ B`；并注明电平制式（TTL / RS-232 / RS-485）与波特率 / 数据位 / 停止位 / 校验位。
- **可枚举确定的连接**（设备 + **VID / PID** 等）→ **可略过**逐引脚确认，但**必须**写明枚举到的**实际设备**；**仅当该连接项由枚举即可完全确定、且不含人工跳线时才可略过**：若用 USB 转串口模块跳线接到目标板 UART 引脚，仍按上条**逐引脚**确认。
- **弹框（先完整展示 → 再弹框；弹框必须自包含整表，且即 C5 的唯一一次交互）**：
  - **先完整展示「全局约定 + 文字说明 + 图示意」，再发起确认**（顺序**禁止颠倒**）；**弹框能合并的必须合并**（同一模块 / 同一组连线一次性列全）。
  - **弹框正文必须逐行照录整张硬件连接表**（全局约定 + 文字说明的**主行与子节点** + 图示意，**一行不省**），且**必须保留「主行顶格 + 子节点为缩进一层的子列表项（`  - └ 丝印：…`）」的两层层级**（**禁止**为省篇幅拍平 / 合并 / 改用 Markdown 表格）：**禁止**只放摘要、**禁止**用省略号或「等 / 略 / 同上 / 其余同表」概括、**禁止**合并行 / 折叠、**禁止**写「详见上一条 / 见上面」、**禁止**只放在弹框之前的正文里（弹框 / 选项卡会遮挡前置内容）；选项只承载「**硬件连接是否已就绪**」这类**短决策**。
  - **逐项自检（强制；未通过禁止输出、禁止弹框）**：输出硬件连接表后、发起弹框前**必须逐项自检**，**每项都必须为「是」**，任一项为「否」→ **原地修正并重新自检**，**禁止**带未通过项进入弹框，**禁止**跳过自检或只写「已自检」：
    1. 图示意**每一行**是否**同时含** MCU 侧标注 + 线号 + 方向 + **对端侧标注**（三段式缺一不可，**尤其不得只画 MCU 侧、漏画对端侧**）；
    2. **图的线号数 = 文字说明主行条数**（**子节点不计入条数**，但**必须逐行照录**），引脚数一并对齐；
    3. 每一根线「从哪根针 → 到哪根针 + 方向」均可核对，且与 ② 文字说明**同名同数**；
    4. 图上**无任何功能描述**（功能描述出现即为放错位置）；
    5. 每个连接项**都有丝印子节点，且该子节点为缩进一层的 Markdown 子列表项**（**父行 `- □ [W1]线 …`、子行 `  - └ 丝印：…`，渲染可见缩进**；物理丝印名 + 针位），**板载 USB 口 / 网口 / 调试口 / 内置模块亦不例外**；**子节点仅用前导空格缩进（折叠顶格）、与主行同列、或并进主行 → 判否**（**例外**：按「丝印前置门槛」判定为**依据文档确实查不到丝印**的连接项，**不写**丝印子节点，**不算缺项**，本项仍判「是」）；
    6. 用户**只看到该弹框、不往上翻任何内容**，即可核对表首全局约定与每一根线。
    7. **主行内是否不含 `丝印` / `依据` / `端点` 字样**？（含即判定层级放错 → 判否，必须下沉为缩进子节点）
    8. **全表是否只有唯一一张图**？（出现 ≥2 张图、每卡一图、或按接口 / 对端分图 → **判否**，必须先合并为唯一图再重新自检）
  - **丝印前置门槛（强制，未过禁止弹框）**：发起弹框前**必须逐条**检查**每个连接项是否带有丝印子节点**，且该子节点已写明 **物理丝印名 + 针位**；**板载 USB 口 / 网口 / 调试口 / 内置模块一律不得省略**，**禁止**只写 MCU 引脚号而不写其物理落点。**任一条连接项缺丝印子节点 / 丝印缺失 / 仅写「板载口」→ 禁止发起弹框，必须先补齐丝印再重新输出**（板版本不明按「板版本不明→全列」并列全列）。**例外（不阻断）**：**实际查阅**评估板说明书 / 原理图后**确实查不到**该连接项丝印时，该连接项**不写丝印子节点**——**既不写占位符，也不写任何推测性落点**（`未知` / `需用户对照板子 / 原理图确认` / `就近 GND 排针` 之类**一律禁止**），且**表内表外均不留任何痕迹**（**禁止**写「未查到 / 不确定 / 待确认 / 需用户核对」等任何说明），该连接项直接**放行、不阻断弹框**。**例外不得滥用**：凡依据材料中查得到的丝印（尤其板载 USB 口 / 网口 / 调试口 / 内置模块）**一律必须写**；**仅在已实际查阅且材料中确实没有**时方可省略，**禁止**未查阅就省略，**禁止**为凑丝印而编造或臆测。
- **确认后冻结**：用户确认后引脚 / 外设 / 对端设备**冻结**；确需变更 → **必须重新确认**。
- 用户否定 → 修正后**重新确认**；无法确认 / 连接不可行 → **终止流程**。

**C4 去重规则（做过即不重复检查）**
- `mrs-prepare-verify` 在生成代码前执行 C1–C3；**若它已完成，`mrs-external-tools` 必须跳过 C1–C3**：**禁止**再次弹框询问设备连接 / 接口选择，**禁止**重复枚举，直接沿用其**验证方案与硬件连接表**进入工具查询。
- **未经 `mrs-prepare-verify`（或它只做了一部分）**时，`mrs-external-tools` **按同一份 C1–C3** 执行。
- **跳过 ≠ 允许幽灵设备**：实际使用前若发现设备**不存在 / 不可用 / 与硬件连接表不一致**，**必须**如实报告并终止（必要时回到 `mrs-prepare-verify` 重新确认），**禁止**用历史记录或替代设备顶替。

**C5 单次交互规则（★ 全程只与用户交互一次）**
- **整流程只允许一次用户交互**：把「**验证方案确认**」「**硬件连接已就绪确认**」**合并进同一次弹框**；**禁止**拆成两次、**禁止**跨轮追问、**禁止**零散反复弹出。
- **顺序不变（禁止颠倒）：先输出 → 再弹框**——弹框前**必须**已把**验证方案全文 + 硬件连接表（C3 规范）**完整写出；弹框正文**必须逐行照录**上一步已输出的**硬件连接表全文**（见 C3），**禁止**只放摘要、**禁止**缩写 / 省略 / 合并。
- **弹框二合一**：① **验证方案**（接受 / 自行输入 / 不接受即终止）；② **硬件连接已就绪确认**（是否已按**硬件连接表全文**逐条就绪，含**表首全局约定（共地 / 供电 / 电平 / 接线顺序）、文字说明逐条连接项与图示意**）；正文**必须完整包含硬件连接表全文**（逐行照录，**禁止**缩写 / 省略 / 合并）。
- **蓝牙追加确认（仅当本次涉及蓝牙 / BLE 功能时强制；追加在弹框最后一项）**：凡第 1 步工程代码分析发现**蓝牙 / BLE 功能**（BLE 外设初始化、蓝牙协议栈 / GATT 服务、蓝牙透传 / 收发接口等），或本次验证需用**主机侧蓝牙适配器**与目标板通信时，**必须**在「验证方案确认 + 硬件连接已就绪确认」二合一正文与选项**之后**、弹框**末尾**追加**确认内容**：
  - **正文追加**：`蓝牙适配器已连接：<C2 实时枚举到的实际蓝牙适配器（实际标识 + 实际设备描述 + 状态）>`；枚举为空 / 无法确认 → **禁止**写「已连接」（**禁止**幽灵适配器），**必须**按 C2 如实报告并请用户接入 / 启用适配器后在**同一轮内**重新枚举再确认。
  - **选项追加（该弹框的最后一项短决策）**：**「蓝牙适配器已经连接（已逐条核对上述实时枚举结果）」**——是 / 否；为**否** → 请用户接入 / 启用后在**同一轮内**重新确认，仍无法确认 → **终止流程**。
  - 该项**必须**并入本次唯一一次弹框，**禁止**单独弹框、**禁止**跨轮追问、**禁止**省略，**禁止**用「蓝牙正常 / 蓝牙可用」等模糊表述代替。
- **WCH-Link 追加确认（仅当本次涉及烧录 / 下载时强制；追加在弹框末尾，蓝牙追加确认之后）**：凡本次需**烧录 / 下载 / 复位**才能完成验证，**必须**在「验证方案确认 + 硬件连接已就绪确认」正文与选项**之后**、弹框**末尾**追加：
  - **正文追加**：`WCH-Link 下载器已连接：<C2 实时枚举到的实际 WCH-Link（实际标识 + 实际设备描述 + 状态）>`；枚举为空 / 无法确认 → **禁止**写「已连接」，**必须**如实报告并请用户接入后在**同一轮内**重新枚举再确认。
  - **选项追加（该弹框的最后一项短决策）**：**「WCH-Link 下载器已经连接（已核对上述实时枚举结果）」**——是 / 否；为**否** → 请用户接入后在**同一轮内**重新确认，仍无法确认 → **终止流程**。
  - 该项**独立于硬件连接表**：**不要求**列出 WCH-Link 的具体连接（调试引脚 / USB 口不在表内展开），**禁止**据此扩展 C3。
  - **同时涉及蓝牙时排序**：蓝牙追加确认在前、WCH-Link 追加确认在后（仍属**同一次弹框**）；**禁止**单独弹框、**禁止**跨轮追问、**禁止**省略。
- **同轮补全例外**：发起确认前若存在无法确定的关键配置，**允许在同一轮内先问配置 → 拿到答案后立即补全接线指引并确认**；只要用户**最终只经历一轮**；**禁止**先问配置、隔一轮再问接线。
- **已确认即不重复**：若本次流程已由 `mrs-prepare-verify` 完成过本规则的一次交互，`mrs-external-tools` **必须跳过、不得再弹框**（见 C4）。
- **确认后冻结**：方案与接线一并冻结（见 C3）；此后**不得**再向用户发起任何询问；确需变更 → **重新走一次**本规则（新的一次交互）。
- **自检**：用户**只看到这一次弹框、不往上翻任何内容**，也能同时知道「验证方案是什么」「**表首全局约定**」「每一根线从哪根针接到哪根针、方向是什么」以及**文字说明里的丝印落点**（丝印落点须位于**缩进一层的子列表项（`  - └ 丝印：…`，渲染可见缩进）**、而非与主行同级或仅用空格缩进；按 C3 例外省略丝印的连接项不受此限）；做不到即为**放错位置**。

## 工作流程

**阶段划分（强制）**：**第 1–3 步 = 规划方案阶段**——**只输出流程**（分析 → 输出并确认验证方案 → 设备 / 接线检查），**禁止**使用查询工具、**禁止**读手册、**禁止**安装工具；**第 4 步起 = 实际执行验证阶段**——**此时才使用查询工具**（查询工具列表 → 选择 → 安装 → 实例数判定 → 调用 → 清理）。

### 第 1 步：工程代码分析（最先执行）
先阅读当前工程源码，分析并记录以下信息，供后续检查与脚本调用使用：
- 使用的调试接口（COM / USB / BLE / 以太网）；
- 固件打印行为（仅启动打印一次 / 固定次数 / 周期性 / 无）；
- 串口参数（波特率 / 数据位 / 停止位 / 校验位）；
- 是否需要复位 / 烧录（下载）后才能验证，以及预计执行时长；**需要下载时**记录**下载方式 = WCH-Link（外置 / 板载）**，并把「**经 WCH-Link 下载 → 复位 → 观察**」与**下载成功判据**（下载工具报告成功 / 校验通过）写入验证方案。

若本次流程已由 `mrs-prepare-verify` 完成工程代码分析，则**直接复用其结论**，**禁止**重复分析。

### 第 2 步：输出「验证方案 + 硬件连接表」并一次性弹框确认（★ C5 唯一一次交互；与 `mrs-prepare-verify` 第 2 步逻辑一致）
**去重（强制）**：若本次流程**之前的 `mrs-prepare-verify` 已输出并确认过验证方案** → 本步**必须跳过**（**既不输出也不弹框**），直接沿用其已确认方案进入第 3 步。
**未跳过时**，按 `mrs-prepare-verify` 第 2 步的**同一逻辑**执行，**顺序（强制，禁止颠倒）：先输出 → 再弹框，且全程只弹这一次（C5）**。发起弹框前**必须先按 C2 完成设备实时枚举**（结果写入硬件连接表与候选设备列表；该枚举即本次 C2 的枚举结果，第 3 步与后续**禁止重复枚举**）：
- **① 先输出**：把验证方案**完整写出**给用户，至少含：验证目标与现象、使用的工具 / 接口、**明确的通过 / 不通过判据**、所需外部硬件与连接、预计时长（要素一项不漏）；其中**硬件连接部分必须按 C3 的硬件连接表规范组织**（**全局约定 + 文字说明 + 图示意**，**覆盖全部连接项、一项不漏**），必要时直接给出**硬件连接表**；

### 第 4 步：查询工具列表并记住（仅实际执行验证时；规划阶段禁止查询）

- **必须重新查询（缓存失效）**：① 本次会话尚无缓存；② 目标工具不在缓存列表中；③ 安装状态可能已变化（刚执行过安装，或缓存中的 `installPath` 已不存在）；④ 用户要求刷新，或进入新会话 / 新任务。
- 重新查询后，**必须**用新结果**覆盖**旧缓存。
- **查询失败处理（终止红线）**：`ide-get-external-toolList-description` 失败（网络请求失败 / 线上接口不可用 / `query_tool_list` 失败等）→ **允许重试一次**；仍失败 → **立即终止并提醒用户**（如实说明失败事实与已重试次数，请检查网络 / MRS 线上接口后再试）。**禁止**在列表不可用时继续验证，**禁止**改用直连串口 / TCP、其他软件或自写脚本等**非 MRS 途径**替代本流程（见强制约束第 33 条）。

### 第 5 步：从缓存中选择工具

**USB 场景强制**：本次验证需要 **USB 枚举或端点信息**时，候选工具**必须**包含并选中 `WCHUSBList`，安装状态不影响选择（见强制约束第 35 条）。

### 第 6 步：检查并按需安装，并结合参数手册判定实例数
检查目标工具的 `hasInstalled`：

- **为 `false`**：调用 `ide-install-external-tool`，其中 `toolID` **必须**使用工具缓存中的准确值（**禁止**改写或臆造）。
  - 安装成功 → 读取**最新安装结果**中 `manual_location` 指定位置的参数手册，并记住 `toolID` 与可执行文件路径（`installPath`）。
  - 安装失败 → 最多再重试 **2 次**（同一工具、同一 `toolID`，**禁止**改写 `toolID` 或换用其他工具）；仍失败 → **终止流程并提醒用户**（说明已重试次数，请检查网络 / 磁盘 / 权限 / 安装源），**禁止**继续后续调用，**禁止**改用本机其他位置的同名 / 同类软件顶替（第 31 条）。重试成功后按上一行继续读取手册与 `installPath`。

**时序（串口 / USB / BLE / 以太网通用）**：先确认接收 / 监听侧就绪，再复位 / 发送（先收后发）；以「数据到达即返回」的短轮询代替固定长 `Start-Sleep`；一问一答严格配对，**按发送顺序**对齐，区分迟到数据；**禁止**多进程并发读同一输出流（第 22 / 23 条）。
**调用前自检**：参数与命令**必须**对照 `manual_location` 手册，调用范式按第 21 / 25 条，经第 24 条静态自检通过后才可调用。

   - **是** → **必须**严格按以下顺序执行，**禁止**颠倒：
     ① 先由 `mrs_pipe_host.ps1` 以 `/pipe` 模式开启串口接收（后台常驻进程，保持不关闭），`open` 成功后 host **立即写入就绪标记 `mrs_pipe_ready.json`**（**多实例**时为该实例的 `mrs_pipe_ready.<实例名>.json`）；
     ② 由主流程轮询**目标实例的**就绪标记确认串口**已成功打开且读取已就绪**（多实例时对每个实例分别轮询）；
     ③ 再执行复位 / 下载；
     ④ 在**短轮询循环**中持续 `read`（每次 `/timeout` 取 1500ms）累积数据，一旦读到内容立即返回；同时设一个**总超时上限**（如 30s）兜底，读到数据即提前结束。**禁止**用固定长 `Start-Sleep` 空等。
   - **否** → 可按常规顺序操作。
   **禁止**在串口接收未就绪时就执行复位 / 下载，否则会丢失启动阶段打印。
   **含 WCH-Link 下载时**：执行复位 / 下载**前**必须确认 C2 枚举到的 WCH-Link **仍在册**；已消失 / 无法确认 → **禁止**下载，如实报告并终止（**禁止**改用其他调试器或串口 ISP 顶替）。
   **发送与接收的时序**（软件发送 / 接收类工具同样适用）：**必须先确认接收侧已就绪，再触发发送或复位**（先收后发），**禁止**边发边等或依赖固定 `Start-Sleep` 对齐；发送与读取**禁止**在同一时刻并发抢用同一输出流，`read` 与发送由**同一方**按固定顺序执行。
   **结束条件判定**：`read` 循环的结束条件**必须**根据实际工程代码中固件的打印行为（如仅启动打印一次 / 固定次数 / 周期性持续打印）确定，不得盲目套用固定逻辑。
   **等待策略**：必须"以数据到达为事件、短轮询提前返回"，使实际等待 ≈ 下载耗时 + 一个轮询周期；不得为图省事写死数十秒的 `Start-Sleep`。短轮询同样不会遗漏输出：`open` 后捕获缓冲持续累积，轮询只是分批取走。
   串口参数（波特率 / 数据位 / 停止位 / 校验位）**必须**与固件配置一致，否则输出为乱码，无法作为验证依据。

25. **路径含空格安全（启动脚本必须用相对 `-File` + `-WorkingDirectory`）**：`Start-Process -ArgumentList` 会把数组拼成命令行字符串，**任何含空格的取值都会被拆开**（与第 21 条同源）。因此：
    - 启动两个通用脚本时**必须**用第 0 节预检得到的 `$psExe`（`pwsh` 或 `powershell.exe`）作为 `-FilePath`，并用 `-WorkingDirectory $ScriptDir` 指定脚本目录，`-ArgumentList` 中只出现**脚本文件名**（如 `'mrs_pipe_host.ps1'`），**禁止**把脚本完整路径放进 `-ArgumentList`，也**禁止**把 `pwsh` 写死（5.1 环境没有 `pwsh`）。
    - exe 路径与工作目录**必须**通过继承环境变量传递——`$env:MRS_PIPE_EXE` / `$env:MRS_PIPE_WORKDIR`（多实例且各实例 exe 不同时用实例级 `$env:MRS_PIPE_EXE_<实例名>`，host 会优先取它；**禁止**用 `-Exe` / `-WorkDir` 传含空格的路径）；host 与 send **必须**取到同一个 `MRS_PIPE_WORKDIR`。
    - 命令内容**必须**走命令文件（第 21 条），**禁止**用引号拼接规避拆分。
    - **禁止**改写脚本本身去绕过这些规则（见第 2 条）。

    - **禁止**对脚本所在目录做递归删除 / 清空（如 `Remove-Item $ScriptDir -Recurse`、`rd /s`、`del /s`），**禁止**以「清理临时文件」为名连带删除技能目录内的任何文件。

29. **【清理交互与容错】删除自建临时文件 / 目录禁止询问，删除失败即直接跳过**：清理阶段（第 8 步 / 第 20 条）删除**本次流程自己创建的临时文件 / 目录**（命令文件、就绪 / 结果 / 停止标记、可写性探测文件、自建日志、下载 / 解压临时目录等）时，**必须**遵守以下三条：

    - **失败即跳过**：单个文件 / 目录删除失败（被进程占用、权限不足、路径暂时不可删等）时，**必须**立刻**跳过该项**、继续清理其余项；**禁止**因单项失败而中断 / 终止流程，**禁止**就该项反复重试把流程卡住，**禁止**因此向用户提问或请求提权。跳过只记录在流程内部，**不得**升级为流程错误，**不得**影响最终结论。

    - 清理情况仍按**第 28 条**处理：最终报告**禁止**提及临时文件、残留、清理过程或跳过项。

31. **【安装失败重试上限 · 禁止另寻同类软件】**：安装目标工具失败时，**必须**按以下三条执行，**禁止**任何形式的「换个软件顶替」：
    - **可重试，但最多两次**：首次安装失败后**允许**重新安装，**最多再重试 2 次**（累计安装调用最多 3 次）；每次重试**必须**仍调用 `ide-install-external-tool` 安装**同一目标工具**，并**必须**使用工具缓存中的准确 `toolID`；**禁止**改写 / 臆造 `toolID`，**禁止**改换为其他工具 ID 或借机安装其他工具（授权边界见第 11 条）。
    - **两次重试后仍失败 → 终止流程并提醒用户**：**必须**立即停止本次流程，如实告知用户「目标工具安装失败且已重试两次」，提醒用户检查网络 / 磁盘空间 / 权限 / 安装源或稍后重试；**禁止**在安装失败后继续执行任何调用步骤，**禁止**把失败略过或擅自降级处理。
    - **禁止去本地其他位置寻找类似软件**：安装失败时，**禁止**改用本机其他目录 / 其他路径下的同名或同类软件顶替——包括但不限于自行探测到的 exe、其他已安装工具、系统自带工具、其他工具的 `installPath`、注册表 / 环境变量 / `PATH` 中的同类程序；**禁止**绕过 `ide-install-external-tool` 自行下载、解压、复制、链接或指向别处的软件；**禁止**把上述任何「本地凑合用」写法写进方案、作为备选或降级方案。
    - 本条只针对**安装失败**这一情形；安装成功（含重试成功后）仍按第 6 步继续使用该工具的 `manual_location` 与 `installPath`，不受影响。
32. **【进程状态检测 · 被安全软件拦杀时清理并重试一次】**：脚本 / 工具进程可能被杀毒软件、EDR 等**拦截或拦杀**（表现为「进程一启动就退出」「就绪标记始终不出现」「状态文件 `phase=error` 或停在 `starting` / `tool-started`」），**必须**按以下四条处理：
    - **及时检测（禁止只等固定超时）**：启动 host / 发送进程后，**必须**用**短轮询**（间隔 ≤ 500ms）同时监视三样东西：① `Start-Process -PassThru` 拿到的进程句柄 `HasExited`；② 状态文件 `mrs_pipe_state<suffix>.json` / `mrs_pipe_send_state<suffix>.json` 的 `phase`；③ 该实例的就绪标记是否出现。轮询中**一旦进程退出就立即停止等待**并判定该次启动失败，**禁止**傻等到 `ReadyTimeoutSec` 超时才反应。可用 `mrs_pipe_send.ps1 -Instance <实例名> -Status` 即时查看 host / tool / sender 的 `phase` 与存活状态（`-List` 可看全部实例及其 `PHASE`）。
    - **失败判定**：出现下列任一情形即判该次启动 / 运行失败：`Start-Process` 本身抛错；进程在该实例就绪标记出现**之前**退出；状态文件 `phase=error`；进程已退出而 `phase` 仍停留在 `starting` / `tool-started`；就绪标记存在但其中的 host 进程已不在（证据不足时**禁止**判定失败）。
    - **清理当前状态并重试一次**：
      - **host 启动失败** → 执行 `mrs_pipe_send.ps1 -Instance <实例名> -Reset`（删除该实例的 ready / state / result / stop / send-state 临时文件，并结束该实例遗留的 host / tool / sender 进程），清理干净后**重启 host 一次**。
      - **发送进程失败** → 执行 `mrs_pipe_send.ps1 -Instance <实例名> -Reset -KeepHost`（**只**清该实例的发送状态与遗留发送进程，**保留健康的 host**；**禁止**在 host 正常时用完整 `-Reset` 连 host 一起杀掉），然后**重发一次**。
      - 清理**只限该实例自己的文件与进程**，**禁止**触碰通用脚本、`.mrs` 目录或其他实例；**host 与发送进程各自只允许重试一次**（即每个进程最多「首次 + 重试 1 次」）。
    - **仍失败 → 终止流程并提醒用户**：重试一次后仍失败，**必须**立即终止本次流程，并提醒用户「脚本或工具可能被杀毒软件 / 安全软件拦截或隔离」，建议把本技能目录、两个通用脚本、PowerShell 引擎与工具 exe 加入安全软件信任 / 白名单后重试；**禁止**再次重试（第 1 条红线仍适用），**禁止**改用本机其他位置的同名 / 同类脚本或软件顶替（见第 31 条）。
    - **脚本文件本身被删除 / 隔离**：若 `Test-Path` 发现 `mrs_pipe_host.ps1` / `mrs_pipe_send.ps1` 已不存在（疑似被安全软件隔离），**无法重试**，**必须**立即终止并如实报告所缺脚本名与本技能目录（见第 26 条），**禁止**从其他位置复制 / 下载脚本顶替。
    - 本条的重试是**被安全软件拦杀**的专用例外（与第 1 条例外一「非正常退出」并列），**不得**当作常规排障重试；**禁止**在无失败判定依据时重试。
33. **【在线列表获取失败 · 重试一次后终止并提醒】**：`ide-get-external-toolList-description` 是**实际执行验证**（第 4 步起）的**前置条件**（规划方案阶段第 1–3 步**禁止**查询）；进入该阶段后**必须**先成功获取工具缓存。查询失败（网络 / 线上接口不可用、`query_tool_list` 失败等基础设施类错误）→ **允许重试一次**；仍失败 → **立即终止并提醒用户**（说明失败事实与已重试次数，请检查网络 / MRS 线上接口后重试），**禁止**继续后续步骤、**禁止**无缓存臆造工具 / `toolID` / 路径 / 参数（第 10 条）、**禁止**改用直连串口 / TCP、其他软件或自写脚本等**非 MRS 途径**替代本流程。本条与第 31 / 32 条的重试-终止策略同级；终止仅指本次流程结束，用户恢复环境后可重新走完整流程。
34. **【工具异常退出 · 结束其他所有工具实例进程并终止流程】**：验证进行中任一工具（实例）**非正常退出**（工具进程消失而 `phase` 非 `exited`、`phase=error`、崩溃 / 报错终止 / 被占用退出、host 检测到工具已死）时，**必须**按以下顺序执行，**禁止**继续验证：
    - **立即停止**：不再发新命令、不再复位 / 下载、不再追加测试轮。**本条优先于第 32 条**：工具进入 `ready`（已就绪、验证进行中）之后的异常退出**不再适用**就地重试；仅**启动阶段**且证据指向被安全软件拦杀的，仍按第 32 条重试一次（重试成功即继续，重试仍失败按第 32 条终止，并同样执行下面两条）。

    - **禁止顶替与降级**：**禁止**改用本机其他位置的同名 / 同类软件、其他已安装工具、其他实例、自写脚本或任何**非 MRS 途径**继续验证（与第 31 条同级）；**禁止**在同一流程内重复启动任何实例（第 1 条红线仍适用）。
    - **收尾**：按第 8 / 20 条**全量清理**本次流程的临时文件（删除不询问、单项失败按第 29 条跳过），**两个通用脚本与 `.mrs` 目录必须保留**。
    - **必须报告（一次，正文输出，不弹框）**：① 哪个工具 / 哪个实例异常退出；② 判定依据（`phase` 取值、进程已退出、状态文件中的 `detail`）；③ 已按本条结束了其他哪些实例；④ 已完成的验证动作与已得出的结论、**因终止无法判定的判据**（**禁止**把未验证的写成通过 / 不通过）；⑤ 建议用户排查原因（连接 / 供电 / 占用 / 安全软件等）后**重新走一次完整流程**。展示与报告遵守第 28 / 30 条（**禁止**提及临时文件 / 清理 / 残留 / 工作目录，**禁止**显示 `toolID`）。
    - 与第 1 条例外一不冲突：例外一允许的是**清理后重新走一次完整流程**（新流程），**不是**在同一次流程内继续或重试。

    - **触发判定（只认这两条，任一命中即适用）**：① 本次验证**需要 USB 枚举**（列出 / 确认识别本机 USB 设备清单，含在册状态、VID / PID、设备描述等）；② 本次验证**需要获取 USB 端点信息**（端点地址、方向、传输类型、最大包长等端点描述信息）。
      - **不触发**：仅串口收发 / 抓打印 / 网络验证等**不需要枚举或端点信息**的场景；**C2 的 PowerShell 实时枚举不算触发**（它只是主机侧设备在线性检查）。
    - **必须动作（顺序固定）**：第 4 步工具缓存中按 `toolname` 精确检索 **`WCHUSBList`**（取值**一律来自缓存**，**禁止**臆造 `toolID` / 路径）→ `hasInstalled: false` 时**必须**先按第 6 步调 `ide-install-external-tool` 安装（失败按第 31 条：最多再重试 2 次，仍失败即终止，**禁止**改用其他软件顶替）→ 安装后**必须调用**它完成 USB 枚举 / 端点信息获取。
    - **当普通工具对待**：与其他工具同流程、同红线——按第 6 步依据其 `manual_location` 手册**判定实例数**（够用只开一个），按第 7 步**只用两个通用脚本**调用（host `/pipe` 常驻 + send 发命令）；**禁止** `Start-Process` 直接启动其 exe、**禁止**另写脚本替代、**禁止**当一次性命令行使用（第 2 / 26 条）。
    - **时机**：**仅实际执行验证阶段（第 4 步起）**；**规划方案阶段与 C2 一律不改**——仍用 PowerShell 实时枚举，该阶段**禁止**查询 / 安装 / 调用本工具（第 17 条）。
    - **多轮验证**：后续每轮需再枚举 / 再取端点时，**一律向同一实例发命令**（`mrs_pipe_send.ps1`），**禁止**重复启动该实例（第 1 条红线；第 32 条例外除外）。
    - **结果**：枚举结果与端点信息必须写入验证结论及硬件连接表对应项（端点需写明地址 / 方向 / 类型 / 包长），并与 C2 已冻结结果交叉印证；**禁止**用历史记录 / 缓存 / 幽灵设备充当枚举结果。**工具手册不提供所需端点信息时，不得臆造**，如实报告并按终止规则处理。
    - **不得跳过**：**禁止**以「未安装」「已有 PowerShell 枚举结果」等理由跳过本工具（第 18 条同级）；缓存中查无该工具 → 按第 4 步**重新查询一次**，仍无 → 如实报告并**终止**（第 10 条）。

### 0. 运行前预检（每次调用脚本前必须先做）

> 本节**仅**预检**本机 PowerShell 引擎**，用于决定运行方式（`pwsh` 还是 `powershell.exe`）。
> **禁止**把工具的任何启动 / 自检 / 响应测试纳入预检——工具**默认功能正常**，按 `manual_location` 手册直接调用即可（见强制约束第 19 条）。
> 调用前**必须**再按强制约束第 24 条做参数与调用方式自检，通过后方可调用。

```powershell
# 探测可用引擎与版本，先决定运行方式；结果存入 $psExe，后续一律用 & $psExe / Start-Process $psExe 调用
$psExe = "$env:WINDIR\System32\WindowsPowerShell\v1.0\powershell.exe"   # 缺省：Windows PowerShell 5.1
$pwshCmd = Get-Command pwsh -ErrorAction SilentlyContinue
if ($pwshCmd) {
    $ver = & $pwshCmd.Source -NoProfile -Command '$PSVersionTable.PSVersion.ToString()'
    $major = 0
    try { $major = [int](($ver -split '\.')[0].Trim()) } catch { $major = 0 }
    if ($major -ge 6) { $psExe = $pwshCmd.Source; "ENGINE=pwsh; VERSION=$ver" }
    else { "ENGINE=powershell; VERSION=$ver" }      # pwsh 版本异常：退回 5.1
} else {
    "ENGINE=powershell; VERSION=$($PSVersionTable.PSVersion)"   # 仅 5.1：powershell.exe + -ExecutionPolicy Bypass
}
"PS_EXE=$psExe"
```

判定规则：
- `ENGINE=pwsh` 且 `VERSION` 主版本 ≥ 6 → `$psExe` 取 `pwsh` 的完整路径。
- 否则仅有 Windows PowerShell 5.1 → `$psExe` 取 `powershell.exe`，启动时保留 `-ExecutionPolicy Bypass`。
- 后续第 4 节的 `& $psExe ...` / `Start-Process $psExe ...` 一律使用该变量，**禁止**把 `pwsh` 写死（5.1 环境没有 `pwsh`）。

> **Windows PowerShell 5.1 兼容性**：
> - 两个通用脚本 `mrs_pipe_host.ps1` / `mrs_pipe_send.ps1` 是**纯 ASCII + 兼容 5.1 语法**（不使用 `??` / `?.` / 三元 `? :` / ForEach-Object -Parallel 等 PS7 专属写法），命名管道用 `::new()`（PS 5.0+ 支持），JSON 状态文件用 .NET `WriteAllText` 以 **UTF-8 无 BOM** 写入，5.1 与 7+ 产物一致。
> - **本节的 PowerShell 片段含中文注释**：Windows PowerShell **5.1 会把「无 BOM 的 UTF-8 .ps1」按 ANSI 解码**，若把片段另存为 `.ps1` 文件再用 5.1 运行，**必须存为 UTF-8 with BOM**（或去掉中文）；直接以 `-Command` 内联执行、或只调用随技能分发的纯 ASCII 脚本，则不受影响。

### 1. 两段式脚本架构（固定脚本，必须遵守）

调用 `/pipe` 模式的 MRS 工具（串口助手 / USB 分析仪 / BLE 调试工具）时，**必须**使用**两个独立脚本**（即随技能分发的两个通用脚本），**禁止**合并为单脚本、**禁止**另写替代脚本：

| 脚本 | 角色 | 生命周期 |
| --- | --- | --- |
| `mrs_pipe_host.ps1` | **管道常驻进程**：以 `/pipe` 启动**一个**工具实例（`-Instance <实例名>` 指定实例；省略即单实例），持有该实例的 stdin（写管道）与 stdout（读管道），对外暴露命名管道 | 全程常驻，**禁止**中途关闭；**一个实例只启动一次** |
| `mrs_pipe_send.ps1` | **发送进程**：连接**目标实例**的命名管道向该实例发送命令（`-Instance <实例名>` 选择要通信的实例；省略即单实例）；支持**持续发送**直到该实例任务结束 | 按需多次启动（可对**不同实例分别**启动），任务结束后退出 |

**为什么必须两个脚本**：两个脚本是独立进程，无法共享同一个子进程的 stdin。因此**必须**用**命名管道**做中转：

```text
发送脚本 → 命名管道 → host 转发到工具 stdin → 工具 stdout → host 回写命名管道 → 发送脚本
```

**约定文件**（均放在按第 12 条优先级选定并可写的 `$WorkDir`；流程中**必须**显式设置 `$env:MRS_PIPE_WORKDIR`，**禁止**依赖脚本内部的 `<TEMP>\mrs_pipe` 兜底）：

- `mrs_pipe_ready<suffix>.json`：**实例**就绪标记，含命名管道名、实例名、host / tool 进程 PID；发送脚本**轮询到该文件出现**后才可连接，主流程据此确认「`open` 后接收已就绪」再执行复位 / 下载。
- `mrs_pipe_state<suffix>.json`：**host 生命周期状态**，`phase` 取值 `starting` → `tool-started` → `ready` → `exited`，异常时为 `error`（含 `detail` 原因），并带 `hostPid` / `toolPid`；供主流程**及时**判断进程是被拦杀还是正常退出，也是 `-Status` / `-Reset` 的依据。
- `mrs_pipe_result<suffix>.txt`：**该实例**的工具输出累积落盘，供主流程核对。
- `mrs_pipe_stop<suffix>.flag`：**该实例**的停止标记；主流程创建它即表示该实例**任务结束**，对应 host 与发送脚本据此退出。
- `mrs_pipe_send_state<suffix>.json`：**发送进程状态**，`phase` 取值 `starting` / `done` / `error`（含 `detail` 与 `sent` 条数）；主流程据此判断发送进程是否被拦杀或中途失败，**不依赖**退出码（`Start-Process` 带重定向时 `ExitCode` 可能取不到）。
- `mrs_cmds<suffix>.txt`：**该实例**的命令文件，发送进程的默认命令来源（**首选的命令传递方式**，避免 `-ArgumentList` 空格拆分）。

> **`<suffix>` 实例后缀约定**：**单实例**（未传 `-Instance`）时后缀为空，文件名与历史**完全一致**（`mrs_pipe_ready.json` / `mrs_pipe_result.txt` / `mrs_pipe_stop.flag` / `mrs_cmds.txt`）；**多实例**时为 `.<实例名>`（如 `mrs_pipe_ready.a.json` / `mrs_cmds.a.txt`）。实例名**只能**是字母 / 数字 / `-` / `_`；各实例文件**共用同一个 `$WorkDir`**，只靠后缀区分。实例数**必须**按第 6 步「实例数判定」并依据 `manual_location` 手册确定，**禁止**随意多开。

> 以上均为**本次流程的临时文件**：流程结束后**必须全部删除**（见强制约束第 20 条），一个都不留；**两个通用脚本保留**。若 `$WorkDir` 为工程目录下的 `.mrs` 目录，则只删除其中的这些临时文件，**`.mrs` 目录本身保留**（即使由本次流程新建，也**禁止**删除）。

**必须遵守**：
- **禁止**用 `Start-Process` 直接启动工具本身，**必须**启动 `mrs_pipe_host.ps1`；`Start-Process` **不得**加 `-Wait`，保留 `-WindowStyle Hidden` 与 `-PassThru` 以便拿到进程句柄。
- **每个实例只启动一次**：实例数按第 6 步判定；启动必须由 host 以 `/pipe` 完成并常驻不关闭；**禁止**重复启动同一实例，后续操作一律通过命令文件向对应实例发命令（第 1 条）。
- **禁止**在流程中重新生成 / 覆盖 / 改写脚本（第 2 条）；脚本是**纯 ASCII + 兼容 PowerShell 5.1** 的实体文件，**禁止**改动。
- **禁止**在 `open` 与 `read` 之间写固定长 `Start-Sleep` 等下载：`open` 成功后 host 写就绪标记，主流程轮询到标记再触发复位 / 下载，随后用**短超时 `read` 轮询**取数据；仅为保持 stdin 不关闭而在命令间等待可短 `Start-Sleep`（≤1s），**禁止**当作等下载手段（第 5 / 22 条）。
- 启动方式见强制约束第 25 条（`$psExe` + `-WorkingDirectory $ScriptDir`，`-ArgumentList` 只放脚本文件名）。

### 2. 脚本一：管道常驻进程（`mrs_pipe_host.ps1`）接口与协议

职责：以 `/pipe` 启动**一个**工具实例（该实例全程只启动一次）→ 对齐握手行 → 建命名管道服务端 → 写就绪标记 → 循环接收发送命令并转发、回写响应 → 收尾退出。**一个 host 进程 = 一个工具实例**；多实例时每个实例各起一个 host，用 `-Instance <实例名>` 区分。全程维护 `mrs_pipe_state<suffix>.json`（`starting` → `tool-started` → `ready` → `exited`，异常为 `error`）。

> **实体文件即唯一实现**：脚本随技能分发、只在本技能目录（见第 7 步），**只允许直接调用**；本文**不内嵌源码**，**禁止**凭本文重写 / 覆盖脚本，**禁止**在别处生成替代脚本（第 2 / 26 条）。脚本缺失或损坏 → **停止并报告**；疑似被安全软件隔离 → 按第 32 条终止并提醒用户。
> **默认工具启动即正常**：本脚本的 `/pipe` 启动**就是正式流程的第一次调用**，**禁止**在它之前做任何启动测试或功能探测（第 19 条）；握手行**仅用于对齐输出流**，超时（默认 20s）只记日志、**不中断流程**。

**接口**：`-Exe`（回退 `$env:MRS_PIPE_EXE_<实例名>` → `$env:MRS_PIPE_EXE` → 脚本同目录唯一 `*.exe`；流程中**必须**显式设置环境变量，**禁止**依赖自动探测）、`-WorkDir`（回退 `$env:MRS_PIPE_WORKDIR` → `<TEMP>\mrs_pipe`）、`-Instance`（实例名，仅字母 / 数字 / `-` / `_`，省略即单实例、文件名与历史一致）、`-HostTimeoutSec`=3600、`-HandshakeTimeoutSec`=20、`-ResponseTimeoutMs`=60000。

**协议与状态（排障用）**：
- **连接**：连接命名管道后 host 先回一行 `{"status":"connected"}`。
- **一问一答**：发送进程每写一行命令，host 转发到工具 stdin 并把工具的一行 stdout 回写；工具无响应时回 `{"status":"timeout"}`（默认 60s）。`/stop` 命令或 `mrs_pipe_stop<suffix>.flag` 均令 host 收尾退出。
- **单一读取方**：host 始终复用同一个未完成的 `ReadLineAsync` 任务 + 超时读取，**不会**因工具无响应永久挂死，也**不会**出现两个读取方抢同一输出流；**禁止**再引入第二个读取方（第 22 条）。
- **状态文件**：`mrs_pipe_state<suffix>.json` 含 `phase`、`detail`、`hostPid`、`toolPid`、`pipe`、`updated`；被拦杀时**停留在被杀前的 phase**（`ready` 前被杀 → 停在 `starting` / `tool-started`），这是识别「被拦杀」的证据。**工具在就绪前已退出则绝不发布就绪标记**，直接写 `error`。
- **收尾**：正常结束写 `exited`、关闭 stdin、必要时结束工具进程、删除就绪标记；异常统一写 `error`、清理后以非 0 退出码退出。

> **同名实例禁止重复启动**：启动时若发现同名实例就绪标记且其 host **仍在运行**（以 `HasExited` 为准，已终止但残留进程表的不算），直接报错退出；实例非正常退出 / 被拦杀后可清理就地重启（第 32 条）。

### 3. 脚本二：发送进程（`mrs_pipe_send.ps1`）接口与协议

职责：连接**目标实例**的命名管道发送命令（`-Instance` 选择实例，省略即单实例），可选 `-KeepAlive` 持续心跳直到该实例停止标记或 `-MaxSeconds`；**全程维护 `mrs_pipe_send_state<suffix>.json`**（`starting` / `done` / `error`），**任何错误都以非 0 退出码结束并写出 `error`**。管理类模式：`-List`（全部实例及 `PHASE`）、`-Status`（目标实例 host / tool / sender 状态与存活）、`-Stop`（结束指定实例）、`-Reset` / `-Reset -KeepHost`（清理实例状态与遗留进程；`-KeepHost` **只**清发送侧、**保留健康 host**）。

> **实体文件即唯一实现**：同第 2 节，**只调用、不重写 / 不另写替代脚本**（第 2 / 26 条）。

**接口**：`-WorkDir`（回退 `$env:MRS_PIPE_WORKDIR` → `<TEMP>\mrs_pipe`）、`-Instance`（同上）、`-CommandFile` / `-Command`（缺省读 `<WorkDir>\mrs_cmds<suffix>.txt`）、`-KeepAlive`、`-KeepAliveCommand`（默认 `read /timeout <IntervalMs>`）、`-IntervalMs`=1500、`-MaxSeconds`=300、`-ReadyTimeoutSec`=30、`-List`、`-Status`、`-Stop`、`-Reset`、`-KeepHost`。`-List` / `-Status` / `-Stop` / `-Reset` 均立即返回、不常驻。

> **命令传递优先级（强制）**：**首选 `-CommandFile`**（逐行写入、含空格安全）；`-Command` **仅**用于不含空格 / 引号 / 空格路径的单一 token（如 `read`）；默认命令文件即 `<WorkDir>\mrs_cmds<suffix>.txt`，**无需**把路径传进 `-ArgumentList`。**禁止**靠手工加双引号规避拆分（第 21 / 25 条）。

> **成功 / 失败判定（主流程用）**：**成功** = `mrs_pipe_send_state<suffix>.json` 的 `phase` 为 `done`；**失败** = `phase` 为 `error`、文件缺失而进程已退出、或进程已退出而 `phase` 仍为 `starting`。**禁止**只看退出码——`Start-Process` 带输出重定向时取不到 `ExitCode`。等待就绪时会**同时检查 host 是否已死 / `phase=error`**，并拒绝信任「host 已死却仍存在的过期就绪标记」，1 秒级报错退出而非空等连接超时。

> **心跳命令**：默认 `read /timeout <IntervalMs>` 只是**串口工具默认值**；其他工具用 `-KeepAliveCommand` 指定——含空格，**必须**以**单个**数组元素传入且值本身不含引号；无法保证时改用「命令文件 + 多次启动发送进程」，**禁止**用引号拼接规避拆分。多实例时**每个实例分别**启动发送进程并各带 `-Instance`；**禁止**对**同一实例**同时启动多个 `-KeepAlive` 发送进程（第 22 条）。

### 4. 主流程编排与清理

1. 按第 0 节预检 PowerShell 引擎并得到 `$psExe`（PS7+ 为 `pwsh`，5.1 为 `powershell.exe`）；**按第 12 条优先级确定可写工作目录 `$WorkDir`：最高优先级是工程目录下的 `.mrs` 目录（`<工程根>\.mrs`，不存在则必须新建，新建成功且可写即选它）；只有新建失败或新建后不可写，才退到工程目录下的子目录（如 `<工程根>\mrs_pipe`），最后才依次退到 `$env:TEMP`、`$env:USERPROFILE`；每一项都必须先做可写探测；所选目录**仅供流程内部使用**，**禁止**在最终报告中说明或提及所选临时目录（见强制约束第 28 条）**；按第 7 步定位 `$ScriptDir` 并确认 `mrs_pipe_host.ps1` / `mrs_pipe_send.ps1` 均存在（**不存在则停止并报告**，**禁止**生成脚本）；并按第 6 步「实例数判定」确定本次的实例清单（**单实例**不传 `-Instance`；**多实例**为每个目标分配一个实例名，如 `a` / `b`，实例名只能是字母 / 数字 / `-` / `_`）。
2. **导出子进程环境变量**（路径不经命令行，规避空格拆分，见第 25 条），并写入命令文件（**首选传递方式**，第 21 条）：
```powershell
$env:MRS_PIPE_EXE     = $installPath     # 工具 exe 完整路径，流程中必须显式设置（脚本在技能目录，自动探测不适用）
# 多实例且各实例 exe 不同时，用实例级变量分别指定（可选；host 优先取它）：
# $env:MRS_PIPE_EXE_A = $installPathA
# $env:MRS_PIPE_EXE_B = $installPathB
$env:MRS_PIPE_WORKDIR = $WorkDir         # host 与 send 必须取同一值（各实例共用同一目录，靠文件名后缀区分）
$cmdFile = Join-Path $WorkDir 'mrs_cmds.txt'          # 多实例：'mrs_cmds.<实例名>.txt'，每个实例一份
Set-Content -LiteralPath $cmdFile -Encoding UTF8 -Value @(
    'open /port <实际串口> /baud <实际波特率>',   # 真实取值必须替换，禁止照抄示例
    'read /timeout 1500'
)
```
3. **启动 host 并做进程健康检查**（**不加** `-Wait`；`-ArgumentList` 中只出现**脚本文件名**）。**单实例**启动一个；**多实例**为每个实例各启动**一次**（只有 `-Instance` 不同）。**启动前必须清理该实例的过期状态**（防止把上次被拦杀残留的 `mrs_pipe_ready` 误认成本次就绪），**启动后必须立刻短轮询「就绪标记 / 进程是否退出」**，**禁止**只等到超时才反应（见强制约束第 32 条）。**失败即清理当前状态并重试一次，仍失败则终止流程并提醒用户**：
```powershell
function Start-HostChecked {
    param([string]$Instance, [int]$ReadyTimeoutSec = 30)
    $sfx      = if ($Instance) { '.' + $Instance } else { '' }
    $readyPath = Join-Path $WorkDir ("mrs_pipe_ready$sfx.json")
    $statePath = Join-Path $WorkDir ("mrs_pipe_state$sfx.json")
    $resetArgs = @('-NoProfile','-ExecutionPolicy','Bypass','-File','mrs_pipe_send.ps1')
    if ($Instance) { $resetArgs += @('-Instance', $Instance) }
    $resetArgs += '-Reset'
    $launchArgs = @('-NoProfile','-ExecutionPolicy','Bypass','-File','mrs_pipe_host.ps1')
    if ($Instance) { $launchArgs += @('-Instance', $Instance) }
    # $psExe 取自第 0 节预检：PS7+ 为 pwsh 完整路径，5.1 为 powershell.exe（禁止写死 pwsh）

    for ($attempt = 1; $attempt -le 2; $attempt++) {
        & $psExe @resetArgs | Out-Null                   # 清理当前状态（首次启动也先清，去掉过期标记）
        $proc = $null
        try { $proc = Start-Process $psExe -WorkingDirectory $ScriptDir -ArgumentList $launchArgs -WindowStyle Hidden -PassThru }
        catch { $proc = $null }                           # Start-Process 自身抛错：疑似被拦截
        $deadline = (Get-Date).AddSeconds($ReadyTimeoutSec)
        while ($null -ne $proc -and (Get-Date) -lt $deadline) {
            if (Test-Path -LiteralPath $readyPath) {
                if (-not $proc.HasExited) { return $proc }            # 就绪且进程存活
                break                                                 # 就绪标记过期 / 进程已死：判失败
            }
            if ($proc.HasExited) { break }                            # 进程已死：立即停止等待
            if (Test-Path -LiteralPath $statePath) {
                $ph = ''
                try { $ph = (Get-Content -LiteralPath $statePath -Raw -Encoding UTF8 | ConvertFrom-Json).phase } catch { }
                if ($ph -eq 'error') { break }                        # host 已明确报错
            }
            Start-Sleep -Milliseconds 200
        }
        # 走到这里说明该次启动失败（疑似被安全软件拦截）：清理状态后进入下一次（最多重试一次）
    }
    throw "实例 '$Instance' 启动失败且重试一次仍失败：脚本或工具可能被杀毒软件 / 安全软件拦截或隔离；请把技能目录、两个通用脚本、PowerShell 与工具 exe 加入信任 / 白名单后重试。"
}
$hostProc = Start-HostChecked -Instance 'a'     # 单实例：省略 -Instance
```
4. **确认就绪后再继续**：上一步返回即已确认该实例「就绪标记出现 **且** host 进程存活」。**多实例**时对**每个实例分别**执行第 3 / 4 步（各自独立判定与重试）；随时可用 `mrs_pipe_send.ps1 -Instance <实例名> -Status` 复查 `HOSTPHASE` / `HOSTALIVE` / `TOOLALIVE`，用 `-List` 查看全部实例及其 `PHASE`。
5. 若固件**复位 / 下载后立即打印**，**必须**在第 4 步之后才执行复位 / 下载，**禁止**颠倒。
6. **启动发送进程并做进程健康检查**（不带 `-CommandFile` / `-Command`，自动读取 `$WorkDir\mrs_cmds.txt`，多实例为 `$WorkDir\mrs_cmds.<实例名>.txt`）；需要持续收数据时再加 `-KeepAlive` 并配数值参数（**均不含空格**）。**多实例**时对**每个实例分别**启动并带该实例的 `-Instance <实例名>`；**成功判定必须看 `mrs_pipe_send_state<suffix>.json` 的 `phase=done`（不看退出码）**，**失败即清理当前状态并重试一次，仍失败则终止流程并提醒用户**（见强制约束第 32 条）：
```powershell
function Start-SenderChecked {
    param([string]$Instance, [string[]]$ExtraArgs, [int]$WaitSec = 60)
    $sfx       = if ($Instance) { '.' + $Instance } else { '' }
    $sendState = Join-Path $WorkDir ("mrs_pipe_send_state$sfx.json")
    $sendArgs  = @('-NoProfile','-ExecutionPolicy','Bypass','-File','mrs_pipe_send.ps1')
    if ($Instance) { $sendArgs += @('-Instance', $Instance) }
    if ($ExtraArgs) { $sendArgs += $ExtraArgs }
    $resetArgs = @('-NoProfile','-ExecutionPolicy','Bypass','-File','mrs_pipe_send.ps1')
    if ($Instance) { $resetArgs += @('-Instance', $Instance) }
    $resetArgs += @('-Reset', '-KeepHost')     # 发送失败只清发送状态、保留 host，避免误杀健康 host
    # 持续收数据（-KeepAlive）时 $WaitSec 必须大于 -MaxSeconds

    for ($attempt = 1; $attempt -le 2; $attempt++) {
        Remove-Item -LiteralPath $sendState -Force -Confirm:$false -ErrorAction SilentlyContinue   # 去掉旧状态，防过期 done 掩盖失败
        $proc = $null
        try { $proc = Start-Process $psExe -WorkingDirectory $ScriptDir -ArgumentList $sendArgs -WindowStyle Hidden -PassThru }
        catch { $proc = $null }                          # Start-Process 自身抛错：疑似被拦截
        $deadline = (Get-Date).AddSeconds($WaitSec)
        while ($null -ne $proc -and (Get-Date) -lt $deadline) {
            if ($proc.HasExited) { break }               # 进程已退出：立即停止等待
            Start-Sleep -Milliseconds 200
        }
        $phase = ''
        if (Test-Path -LiteralPath $sendState) {
            try { $phase = (Get-Content -LiteralPath $sendState -Raw -Encoding UTF8 | ConvertFrom-Json).phase } catch { }
        }
        if ($phase -eq 'done') { return $proc }          # 成功
        & $psExe @resetArgs | Out-Null                   # 失败：只清该实例发送状态与遗留发送进程（保留 host）后重试一次
    }
    throw "实例 '$Instance' 的发送进程失败且重试一次仍失败：疑似被安全软件拦杀；请把技能目录、两个通用脚本、PowerShell 与工具 exe 加入信任 / 白名单后重试。"
}
$null = Start-SenderChecked -Instance 'a'                                                              # 发送命令文件中的命令
$null = Start-SenderChecked -Instance 'a' -ExtraArgs @('-KeepAlive','-MaxSeconds','120') -WaitSec 180   # 持续收数据（多实例：各实例分别调用）
# 管理类（立即返回、不常驻）：-Status 看某实例状态；-List 看全部实例及 PHASE；-Stop 结束某实例；-Reset 清理某实例
& $psExe -NoProfile -ExecutionPolicy Bypass -File (Join-Path $ScriptDir 'mrs_pipe_send.ps1') -Instance 'a' -Status
```
   **参数传递铁律**：命令**一律**走命令文件，**禁止**把含空格的路径 / 命令写进 `-ArgumentList`，也**禁止**靠引号拼接规避拆分；`-Instance` 取值仅字母 / 数字 / `-` / `_`，是安全 token，可直接传（第 21 / 25 条）。
7. **结束条件**：`read` 的结束条件**必须**依据第 1 步分析的固件打印行为（仅启动一次 / 固定次数 / 周期性）判定，不得套用固定逻辑。任务结束时**创建对应实例的停止标记**（单实例 `mrs_pipe_stop.flag`；多实例为每个实例创建 `mrs_pipe_stop.<实例名>.flag`，**必须逐个实例结束**），令 host 与发送进程自然退出，并等待其进程结束：
```powershell

```

9. **清理（保留通用脚本与 `.mrs` 目录）**：删除本次流程生成的**全部**临时文件（`mrs_cmds` / `mrs_pipe_ready` / `mrs_pipe_state` / `mrs_pipe_send_state` / `mrs_pipe_result` / `mrs_pipe_stop`，多实例含各 `<实例名>` 变体，另加探测文件、自建日志、下载 / 解压临时目录；完整清单见第 20 条），删除后**必须逐项确认已不存在**：
```powershell
$targets = @(
    (Join-Path $WorkDir 'mrs_cmds.txt'),
    (Join-Path $WorkDir 'mrs_pipe_ready.json'),

$targets += @(Get-ChildItem -LiteralPath $WorkDir -File -ErrorAction SilentlyContinue |
    Where-Object { $_.Name -match '^mrs_(cmds|pipe_ready|pipe_state|pipe_send_state|pipe_result|pipe_stop)\.[A-Za-z0-9_-]+\.' } |

if ($left) { "RESIDUAL: $($left -join '; ')" } else { "CLEAN: all temp files removed" }
# .mrs 目录必须保留（含本次流程新建的情况）：$WorkDir 为 .mrs 目录时校验其仍然存在
```
