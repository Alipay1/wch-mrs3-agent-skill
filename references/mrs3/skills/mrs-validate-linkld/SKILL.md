# mrs-validate-linkld — link.ld 链接脚本校验

## 1. 目的

WCH（沁恒）RISC-V GCC 工程（CH32V / CH32L / CH32H 等）的 `link.ld` 定义了 FLASH / RAM 的起始地址与长度。配置过大（超过芯片实际容量）会导致链接通过但烧录/运行时越界，配置过小会浪费芯片资源。本技能根据本技能目录下 `mcu_isa.json` 中的芯片最大 Flash / SRAM，校验 `link.ld` 的容量与语法；**检查出问题后必须进行修复**，修复完毕后调用 IDE 工具渲染。

**【执行边界】本技能只负责校验、必要的修复、复检和报告。完成这些步骤后必须立即停止，不得自主触发编译、构建、链接或烧录；只有用户另行明确要求执行上述动作时，才可进入相应流程。**

## 2. 数据源（必须使用本技能目录的配置文件）

- **必须使用本技能目录下的 `mcu_isa.json`**：脚本直接在同目录加载该文件，**不接受路径参数**；不要使用工程里其他位置的 mcu_isa.json。
- 该文件包含多个芯片型号的 `flash` / `sram` 上限数据，以及 `toolchain`、`cores[].mabi`、`cores[].isa_ext` 等。

## 3. 使用流程（Agent 按此执行）
 
0. **【必须】获取当前工程路径**：执行本技能时**必须**先调用 **`mrs-ide-tools_ide-get-projectToOperate`** 工具获取当前工程路径。
   - 该工具为异步任务：返回"任务已提交 (ID: task_xxx)"后，用 **`mrs-ide-tools_ide-get-task-status`** 轮询直到 `任务状态: success`，再从结果中取工程路径（如 `e:\project\CH32H417WEU_USBLoop\V3F`）。
   - **【必须】后续所有步骤的工作目录**：第 0 步之后的所有步骤（定位 link.ld、获取芯片型号、读取/修改 link.ld、执行校验脚本等）的工作目录（cwd）**必须是本步骤获取到的工程路径**——即所有相对路径、文件读写、命令执行都基于该工程路径，禁止切换到其他目录操作；如使用绝对路径也必须是该工程路径下的文件。注意：修改文件必须使用`ide-edit`工具
   - 双核工程可据此确认当前操作的是 V3F 还是 V5F。
1. **定位 link.ld**：调用 **`mrs-ide-tools_ide-get-project-linker-scripts`** 工具获取 link.ld 的目录/路径列表，注意！（必须调用 `mrs-ide-tools_ide-get-projectToOperate`工具输出的路径为当前工具的参数）。
   - 该工具为异步任务：返回"任务已提交 (ID: task_xxx)"后，用 **`mrs-ide-tools_ide-get-task-status`** 轮询直到 `任务状态: success`，再从结果中取 link.ld 路径。
   - 双核工程通常有 V3F、V5F **两份** link.ld（分别在 `V3F/`、`V5F/` 目录，均位于第 0 步工程路径下），结果中应包含两份，需分别校验。
   - 用户主动提供了 link.ld 路径时，可直接使用用户提供的路径，无需再调用工具；相对路径按第 0 步工程路径解析。
2. **确定芯片型号（按优先级）**：
   1. 优先使用**用户告知**的型号；
   2. 用户未告知时，调用 **`mrs-ide-tools_ide-get-project-chipType`** 工具获取（同样为异步任务，需轮询 `get-task-status` 至 success 后取结果）；
   3. 最后才从 link.ld 内容注释、路径、或同目录 `.wvproj/.project/.cproject` 中推断（正则 `CH32[A-Z0-9]+`）。
3. **确定内核**：路径含 `V3F` → v3f；含 `V5F` → v5f；单核工程 → single。无法确定时询问用户或按 single 处理并提示。
4. **执行校验脚本（工作目录为第 0 步获取的工程路径，脚本参数可用相对路径）**：
   **根据操作系统平台选择原生脚本执行**（`validate_linkld.bat` / `validate_linkld.sh` 加载本技能目录的 `mcu_isa.json`）：
      - **Windows 平台 → 执行 `validate_linkld.bat`**（启动器，内部调用 PowerShell 脚本 `validate_linkld.ps1` 实现核心校验）：
        ```
        cmd /c "<skill目录>\validate_linkld.bat" <link.ld路径> [--chip CH32H417WEU] [--core v3f|v5f|single]
        # 双核工程：
        cmd /c "<skill目录>\validate_linkld.bat" V3F\link.ld V5F\link.ld --chip CH32H417WEU
        ```
      - **Linux / macOS 平台 → 执行 `validate_linkld.sh`**（bash 脚本，无需 Python）：
        ```
        bash <skill目录>/validate_linkld.sh <link.ld路径> [--chip CH32H417WEU] [--core v3f|v5f|single]
        # 双核工程：
        bash <skill目录>/validate_linkld.sh V3F/link.ld V5F/link.ld --chip CH32H417WEU
        ```
      - **平台判断**：命令执行环境为 cmd / PowerShell（路径分隔符 `\`，可运行 `.bat`）→ Windows；为 bash / sh（路径分隔符 `/`，可运行 `.sh`）→ Linux/macOS。
   3. **对应平台脚本均不可用时，按第 4 节清单人工逐项检查**。**人工检查时【必须】强制检查 ld 文件中运算符之间是否有空格**：`=`、`+`、`-`、`/`、`%`、`<<`、`>>`、`&`、`|`、`^` 等运算符两侧必须为空白（如 `_estack=...`、`a+b` 均不符合要求）；**注释（含跨行注释）与通配符（`*(.text)`、`.text*` 等）不检查**；`/DISCARD/` 段名、一元负号也不检查。发现不符合的，按第 5 步修复（运算符两侧补空格）。
   脚本直接加载**本技能目录**的 `mcu_isa.json`（不接受路径参数），结果确定、带行号。
5. **发现问题时修复（必须；在工程路径下修改该工程路径内的 link.ld 文件）**：校验存在 ERROR（或需处理的 WARN）时，**必须进行修复**。修复方式为直接修改 `link.ld` 文件（用 `edit` 文件工具，工作目录为第 0 步工程路径），按问题类型修正：
   - **容量超限（ERROR）**：将 `FLASH LENGTH` / `RAM LENGTH` 改为 **≤ 芯片最大容量**（如 `LENGTH = 1024K` 超过 960K → 改为 `LENGTH = 960K`）；
   - **双核合计超限（ERROR）**：调整 V3F / V5F 两份脚本的 LENGTH，使两者之和 ≤ 芯片总容量；
   - **语法错误（ERROR/WARN）**：修正括号配对、ORIGIN/LENGTH 数值格式等；**运算符两侧缺少空格时在运算符两侧补空格**（如 `_estack=ORIGIN(RAM)+LENGTH(RAM);` → `_estack = ORIGIN(RAM) + LENGTH(RAM);`，`LENGTH=480K` → `LENGTH = 480K`）；赋值语句缺分号时补 `;`。**【绝对禁止】计算运算符两侧的数值**：对于运算符两侧均为数字字面量的表达式（如 `64K*2`、`0x1000+0x2000`、`1M/2`、`0x8000-0x1000`、`512K - 256`），**绝对禁止计算其最终值**——不得把 `64K*2` 换算成 `128K` 写入、不得把 `0x1000+0x2000` 合并成 `0x3000`、不得做任何算术运算/单位换算/合并化简，**必须原样保留、原样输出**。
   修复后**重新运行校验脚本，直到全部通过（PASS）**。
6. **汇总报告**：向用户输出校验结论（见第 5 节格式）、发现的问题、已做的修复内容与修复后的校验结果（如"FLASH LENGTH 1024K → 960K，修复后 PASS"）。
7. **停止**：报告完成后结束本技能，**不得继续调用任何编译、构建、链接或烧录工具**。校验通过、修复后复检通过、或用户要求“检查编译前配置”，均不构成执行编译的授权。

## 4. 校验规则清单

| 级别 | 检查项 | 规则 | 说明 |
|---|---|---|---|
| ERROR | 容量 | FLASH 全部区域（多行/`FLASH2` 等）LENGTH **合计** ≤ 芯片最大 flash | LENGTH 支持表达式（如 `448K - 256`、`0x3FC00`、`64K*2`），脚本内置小型计算器统一转十进制后**相加**再比较（仅用于校验比较，不修改文件）；超限即 FAIL |
| ERROR | 容量 | RAM 全部区域（多行/`RAM2` 等）LENGTH **合计** ≤ 芯片最大 sram | 同上 |
| WARN | 容量 | 使用率 ≥ 90% | 按合计计算，提示接近上限 |
| ERROR | 双核合计 | V3F+V5F 的 FLASH/RAM 合计（各自已含多区域求和）分别 ≤ 芯片总量 | 双核工程两份脚本一起校验时执行 |
| INFO | 符号 | ld 中是否存在 `__global_pointer$` | 缺失时仅报告（不影响 PASS），提示 RISC-V GP 优化通常需要定义 |
| ERROR | 语法 | 括号不配对（`{}`/`()`/`[]`，注释剥离后）；MEMORY 块中存在无法解析的行 | 括号缺失会导致链接器解析失败 |
| ERROR | 语法 | 运算符两侧必须有空格（`=`、`+`、`-`、`/`、`%`、`<<`、`>>`、`&`、`\|`、`^` 等） | 如 `_estack=...`、`a+b` 均报错，需修复补空格；**注释与通配符（`*(.text)`、`.text*`）不检查**；**运算符两侧均为数字字面量（如 `64K*2`、`0x1000+0x2000`）时不检查空格，且【绝对禁止】计算其数值最终值，必须原样保留**；`/DISCARD/` 段名、一元负号除外 |
| WARN | 语法 | 区域引用（`>区域`/`AT>区域`/`ORIGIN()`/`LENGTH()`）未定义；赋值语句缺少分号（MEMORY 块外、不含 `{}` 的行中含 `=` 且未以 `;` 或续行符结尾）；INCLUDE 文件不存在 | 未定义区域可能来自 INCLUDE 文件 |

## 5. 输出报告格式

校验完成后向用户输出：

```
link.ld 校验报告
  芯片: CH32H417WEU（最大 flash 960K / sram 896K）  内核: V5F
  区域  配置值        上限      结论
  FLASH ORIGIN=0x40000000 LENGTH=480K  960K   ✅ 通过（50.0%）
  RAM   ORIGIN=0x38000000 LENGTH=448K  896K   ✅ 通过（50.0%）
  结论: PASS
```

FAIL 时逐条列出：`❌ [ERROR] FLASH LENGTH=1024K 超过芯片最大 960K（第4行），建议改为 <= 960K`，并汇总错误/警告数量。

修复后报告示例：

```
link.ld 校验报告（修复后）
  发现: FLASH LENGTH=1024K 超过最大 960K（第4行）
  修复: LENGTH 1024K → 960K（修改 link.ld 第4行）
  复检: ✅ PASS（0 个错误, 0 个警告）
  渲染: 已调用 ide-decorate-diffs（调用后直接返回，无需等待结果）
```

## 6. 注意事项

- **【必须】工程上下文**：每次执行本技能，第一步都必须是调用 `mrs-ide-tools_ide-get-projectToOperate` 获取当前工程路径，禁止跳过该步骤直接猜测工程路径。
- **【必须】工作目录**：后续所有步骤的工作目录必须是第 0 步获取的工程路径，所有文件读写、命令执行、相对路径均基于该路径，禁止在其它目录下操作。
- **【必须】发现问题必须修复**：校验出 ERROR（或需处理的 WARN）后，必须修改 link.ld 文件进行修复，修复后重新校验至 PASS，**不得只报告不修复**。
- **【必须】校验完成即停止**：本技能的终点是校验/修复/复检结果报告；除非用户另行明确要求，否则禁止自主执行编译、构建、链接或烧录。
- **【必须】多区域合计后再比较容量**：ld 中 FLASH/RAM 可能存在多行/多个区域（如 `FLASH`/`FLASH2`、`RAM`/`RAM2`，区域名以 FLASH/RAM 开头即归入同类），脚本会把同类全部 LENGTH **相加**后再与 mcu_isa.json 上限比较；修复时同理按合计调整。
- **【必须】LENGTH/ORIGIN 表达式用计算器转十进制**：`LENGTH = 448K - 256`、`LENGTH = 0x3FC00`、`LENGTH = 64K*2` 等情况，由脚本内置小型计算器统一转成十进制后再计算（仅用于校验比较，**绝不改写 ld 文件**）；含符号/函数（如 `ORIGIN(RAM)`、`ALIGN(4)`）时报告“无法计算”。
- **`__global_pointer$` 缺失仅报告**：ld 文件（注释剥离后）中未出现 `__global_pointer$` 时输出 INFO 提示（不影响 PASS），无需修复。
- **【绝对禁止】计算运算符两侧的数值**：校验与修复全过程中，**绝对禁止**对运算符两侧均为数字字面量的表达式做任何计算——不得求值、不得换算单位（如 `64K*2` → `128K`）、不得合并化简（如 `0x1000+0x2000` → `0x3000`）、不得做加减乘除运算，**必须原样保留、原样输出**；此类表达式也不参与空格检查。注意：这与上一条“容量比较时计算 LENGTH 表达式”不冲突——计算器只用于脚本内部的校验比较，绝不改写文件。
- **【必须】脚本无法运行时的强制人工空格检查**：若对应平台脚本均无法运行（Windows 无 `.bat` 可执行 / Linux、macOS 无 `.sh` 可执行），人工检查时**必须**逐行核对 ld 文件中运算符（`=`、`+`、`-`、`/`、`%`、`<<`、`>>`、`&`、`|`、`^`）两侧是否有空格；**注释与通配符不做检查**；发现缺失必须修复补空格。
- **双核芯片**（CH32H415 / CH32H416 / CH32H417）：V3F 与 V5F 各有一份 link.ld，必须**分别校验**，且**两份合计**不能超过芯片总容量；两份脚本请同时传给脚本以自动做合计校验。
- 芯片型号在 mcu_isa.json 中找不到时，停止容量校验并请用户确认型号（注意型号末尾温度代码，如 `CH32H417QEU6` 在库中为 `CH32H417QEU`）。
- 校验脚本：Windows 版（`validate_linkld.bat` 启动器 + `validate_linkld.ps1` 核心逻辑，PowerShell 实现）、bash 版（`validate_linkld.sh`），逻辑与参数一致；**按平台选择：Windows → `.bat`（内部调用 `.ps1`），Linux/macOS → `.sh`**；全部不可用时按第 4 节清单人工逐项检查；退出码：0 = PASS，1 = 存在 ERROR，2 = FATAL（文件/配置缺失、无法推断型号）；可加 `--quiet` 只输出结论。
