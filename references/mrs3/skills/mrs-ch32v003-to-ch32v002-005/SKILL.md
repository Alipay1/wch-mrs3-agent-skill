# CH32V003 工程 → CH32V002 / CH32V005 工程 迁移指南

## 适用前提

- 源工程基于 **WCH 标准外设库（SPL）**，不是 HAL / 寄存器直写工程。
- 目标芯片是 **CH32V002** 或 **CH32V005**（本技能不支持反向，也不支持转到 V004/V006/V007）。
- 封装映射只覆盖以下对应（源工程用了别的封装 → 停下询问）：

| V003 源封装 | V002 目标 | V005 目标 |
|---|---|---|
| CH32V003F4P6 | CH32V002F4P6 | CH32V005F6P6 |
| CH32V003F4U6 | CH32V002F4U6 | CH32V005F6U6 |
| CH32V003A4M6 | CH32V002A4M6 | 无对应封装 |
| CH32V003J4M6 | CH32V002J4M6 | 无对应封装 |

## 两条入口

| 入口 | 触发条件 | 起点 |
|---|---|---|
| **A：从 V003 客户工程出发**（常规） | 用户给的是 V003 工程，还没有目标工程 | **阶段 0** → 阶段 1–4 |
| **B：工程级转换已完成** | 目标工程骨架已就位，用户代码已复制进 `User/`，只是编译不过或行为不对 | 跳过阶段 0 的转换步骤；**若两条工程属性尚未设置，先补设**（见 0.3），再从**阶段 1** 开始 |

## 最重要的一条原则

**「改名」「删功能」「改逻辑」是三件不同的事，先判定再动手。**

| 判定 | 编译期表现 | 处理 |
|---|---|---|
| 目标库无此符号（改名类） | 报未声明 | 查 `references/02` `03` 的对照表改名，编译器兜底 |
| 目标芯片无此功能（删除类） | 报未声明 | **整句删除**，并确认删掉后功能不退化；属真实功能缺失的在报告列出 |
| 同名但值/粒度已变 | **零提示** | 必须重算，查 `references/02` 2.2 |
| 同名同签名、实现已变 | **零提示** | 必须逐条核对，查 `references/07` |
| 同名同义、仅内部编码不同 | **零提示** | **不要动** —— 用宏名即正确 |

最后一类是本次迁移最容易做错的地方。`DBGMCU_TIM1_STOP` 两侧同名同义但位定义不同、
`GPIO_Speed_30MHz` 两侧同名同义但枚举值从 3 变 1、`FLASH_WRProt_AllPages` 从 `0x0000FFFF` 变 `0xFFFFFFFF` ——
这些位置保留宏名**自动就是对的**，去"修正"数值反而引入 bug。

## 阶段 0 · 工程级转换、工程属性设置与产出校验

**参数（缺一个就问，不猜）**：源工程路径 / 目标路径 / 目标工程名 / **目标型号（CH32V002 或 CH32V005）**。

| 步骤 | 内容 |
|---|---|
| 0.1 | 目标型号由**用户在提示词内指定**，并随提示词传给工程级转换工具 |
| 0.2 | 交给 MRS 内置 `ide-create-project-byConvert` 执行工程级转换。**不自己解析工程文件、不手工搭工程** |
| 0.3 | **设置两条工程属性**（见下）—— 用自然语言交给 MRS 智能体执行即可，**不需要手工改工程文件** |
| 0.4 | 校验产出：模板结构完整 / 模板 `main.c` 已删 / 客户 `.c/.h` 逐个就位 / include 路径已含 / **两条工程属性已按指定设置** |

任一不通过 → 停下报告缺项，**不带半成品进阶段 1**。

### 0.3 工程属性（转换完成后立即执行，共两条）

| # | 属性 | 取值 |
|---|---|---|
| 1 | 工具链 | **GCC15** |
| 2 | 编译属性 | **关闭 M 乘法扩展**；**开启 ZMMUL 扩展**（乘法子集） |

转换一完成，就把这两条属性交给 MRS 智能体设置，用自然语言描述即可，例如：

> 把当前工程的工具链切换为 GCC15；在编译属性里关闭 M 乘法扩展，勾选 ZMMUL 扩展。

**就按上面这两条设置，不需要再去读或核对工程文件。** 目标芯片核使用 ZMMUL 乘法子集，
源工程默认不带这一项，不设置时会沿用源工程的指令集配置，**编译期不报错**，属静默差异。

## 阶段 1 · 工程基线（4 个 🔴 零提示项）

| # | 核对项 | 不通过的后果 |
|---|---|---|
| 1 | **链接脚本 MEMORY 档位与型号匹配**（目标侧 `Link.ld` 是三档注释切换，模板默认选中 62K/8K 档），`__stack_size` 按 V002=512 / V005=512 | 拿到不存在的芯片配置，编译期零提示 |
| 2 | **系统时钟档位**：V003 模板默认 `SYSCLK_FREQ_48MHz_HSE`，目标模板默认 `SYSCLK_FREQ_48MHz_HSI`，**时钟源不同** | 时钟源与源工程不一致 |
| 3 | **库文件未被残留**：库文件名大小写不同（`ch32v00x_` vs `ch32v00X_`），Windows 下混放不报错 | 符号可能错配 |
| 4 | **`.highcode` 段**：源工程若用了 `__attribute__((section(".highcode")))`，目标侧整体不存在该段 | **链接期才炸** |

补充：用户系统文件归位（`system_ch32v00X.c/h`、`ch32v00X_it.c/h`、`ch32v00X_conf.h`）。
默认用**目标侧版本**的 system 文件 + 逐行比对客户改动并移植；客户改过 system 文件时必须在报告中列为改动项。

## 阶段 2 · 机械替换（编译期错误，可依赖编译器兜底）

先跑扫描脚本，把用户代码里所有需要处理的符号一次性列出来。

**优先用 PowerShell 版**（Windows 环境自带，无需 Python）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\scan_v003_symbols.ps1 <目标工程目录> -Target CH32V002
```

**有 Python 环境时**用 Python 版（两版功能、输出完全等价）：

```bash
python scripts/scan_v003_symbols.py <目标工程目录> --target CH32V005
```

| 参数 | PowerShell | Python | 说明 |
|---|---|---|---|
| 工程目录 | 位置参数 | 位置参数 | 必填 |
| 目标型号 | `-Target CH32V002` | `--target CH32V002` | 用于 OPA 等按目标分流 |
| 全目录扫描 | `-All` | `--all` | 连 `Peripheral/Core/Startup/Ld` 一起扫 |
| JSON 输出 | `-Json` | `--json` | 供程序消费 |

- 两版都在 Windows 上默认以 **UTF-8** 输出，中文提示不会乱码。
- `.ps1` 以 **UTF-8 with BOM** 保存，`Set-ExecutionPolicy` 受限时用 `-ExecutionPolicy Bypass` 调用。
- 退出码：`0` 正常 / `2` 参数或数据文件错误。
- 脚本输出四类：`[必须人工核对]` / `[需改名]` / `[建议删除]` / `[提示]`。
- 默认跳过 `Peripheral/` `Core/` `Startup/` `Ld/`（工程级转换后已是目标侧版本），
  **不跳过 `Debug/`** —— 其中的 `debug.c` 含 USART 重映射等工程级配置，需一并核对。

按输出处理：
- `[需改名]` —— 时钟族（宏 + 函数 + 结构体成员）、`FLASH_ReadOutProtection`、`EXC_IRQn`、头文件大小写含路径
- `[建议删除]` —— 目标芯片无此功能（ADC 校准、USART 智能卡/同步时钟、`RCC_FLAG_LPWRRST` 等）

## 阶段 3 · 语义替换（人工判定，编译器不会提示）

按以下 6 块逐一核对，逐条依据见对应 references：

| # | 块 | 关键点 | 依据 |
|---|---|---|---|
| 1 | **FLASH** | 页粒度 64B→256B（循环擦写会连带擦掉相邻数据）、编程 API 整体换成 Fast 编程、写保护 16→8 页/组、读保护改名去参 | `references/05_flash.md` |
| 2 | **GPIO** | 速度宏统一为 `GPIO_Speed_30MHz`、**重映射参数必须按目标引脚重选**（同名宏值也不同） | `references/06_gpio.md` |
| 3 | **OPA** | V002 → 整句删除 + 报告告知；V005 → 整体按 V005 OPA 库重写（结构体成员 2→15） | `references/04` 4.4 |
| 4 | **ADC / USART / SPI / PWR** | ADC 位宽 10→12bit、无校准/无 DLYR；USART 无智能卡/同步时钟；SPI 无 CHSIDE/UDR；PWR 档位体系不同 | `references/04` `02_macro-delta.md` |
| 5 | **core_riscv / 低功耗** | `core_riscv.h` 与 `.c` 整份换目标侧；`WFE` / `WFItoWFE` / `_WFE_` 在目标侧不存在；`_WFE`/`__WFE` 实现不同 | `references/08_core-riscv.md` |
| 6 | **零提示项总表** | 同名同签名但实现已变的 8 组（含 DBGMCU 芯片 ID、RCC_SYSCLKConfig 的 HSI 校准、GPIO_PinRemapConfig） | `references/07_func-behavior.md` |

## 阶段 4 · 编译与上机

1. 在 MounRiver Studio 2 侧编译。**本技能不跑命令行构建。**
2. 按编译错误类型四轮迭代：
   - 第一轮：预处理 / 语法（头文件、宏名、改名族）
   - 第二轮：类型 / 结构体成员（`RCC->PB2PCENR` 这类）
   - 第三轮：链接（残留符号、`.highcode` 段）
   - 第四轮：行为核对（阶段 3 的 6 块）
3. 上机验证清单：FLASH 擦写（重点：模拟 EEPROM 的 256B 页边界）、延时、时钟源、串口波特率、GPIO 电平、低功耗唤醒。

## 交付报告

迁移完成后输出 markdown 清单，必须包含：

- **改动项** —— 按文件列出实际修改
- **删除项** —— 删掉的函数/语句及其原因
- **需人工确认项** —— 脚本标记为 `[必须人工核对]` 但无法从源码判断的
- **功能缺失告知** —— 目标芯片不具备的原功能，按目标型号分流：
  - ADC 校准、ADC DLYR
  - USART 智能卡 / 同步时钟 / 单线半双工 / 8 倍过采样
  - `RCC_FLAG_LPWRRST`（无低功耗复位标志查询）
  - SPI `CHSIDE` / `UDR`
  - **OPA**：源工程用了 OPA 且目标是 **V002** → 在此告知「目标芯片无 OPA 功能」
- **封装告警** —— A4M6 / J4M6 转 V005 无对应封装

## scripts

| 文件 | 用途 |
|---|---|
| `scripts/scan_v003_symbols.ps1` | 扫描脚本（**PowerShell 版，Windows 首选**，无需 Python 环境） |
| `scripts/scan_v003_symbols.py` | 扫描脚本（Python 版，与上面等价） |
| `scripts/data.json` | 两份扫描脚本共用的对照数据（由两侧 EVT 全量扫描生成） |

> **维护约定（必须遵守）**：`scan_v003_symbols.ps1` 与 `scan_v003_symbols.py` 是**同一功能的两份实现**，
> 共用同一份 `data.json`。修改判定规则、分类、提示文案、命令行参数或输出格式时，
> **两份脚本必须同步更新**，并保证同一工程、同一参数下两者输出一致（文本逐行相同、JSON 结构相同）。
> 改动 `.ps1` 时须保持 **UTF-8 with BOM** 编码，否则 Windows PowerShell 5.1 会按 ANSI 读取，中文字符串会解析失败。
>
> **默认扫描范围亦为既定行为**：默认跳过 `Peripheral/` `Core/` `Startup/` `Ld/`，仅 `-All` / `--all` 时全扫。
> 不要改成默认全扫。
