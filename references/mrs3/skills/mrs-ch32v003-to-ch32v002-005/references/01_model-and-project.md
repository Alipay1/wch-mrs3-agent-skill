# 01 型号、封装与工程基线

数据来源：工作区 `CH32V003EVT/`（V003 EVT）与 `CH32V006EVT/`（V002/004/005/006/007 共用 EVT），
以及硬件工程师提供的 `003-002、005规则.md`。两侧 EVT 版本：V003 库 2.1 / 目标库 1.5。

---

## 1. 封装映射

| V003 源封装 | V002 目标 | V005 目标 |
|---|---|---|
| CH32V003F4P6 | CH32V002F4P6 | CH32V005F6P6 |
| CH32V003F4U6 | CH32V002F4U6 | CH32V005F6U6 |
| CH32V003A4M6 | CH32V002A4M6 | **无对应封装** |
| CH32V003J4M6 | CH32V002J4M6 | **无对应封装** |

**A4M6 / J4M6 转 V005 时不停止**，转 V002 正常。
V005 只有 F6P6 / F6U6 两种封装，源工程是 A4M6/J4M6 且用户要转 V005 时，
按「无对应封装」处理，并在最终报告中列出，不自行改封装。

V002 与 V005 全部封装对应关系以 `003-002、005规则.md` 第 1–5 行为准。

## 2. 内存与链接脚本

| 型号 | Flash | RAM | `__stack_size` |
|---|---|---|---|
| CH32V003 | 16K | 2K | 256 |
| CH32V002 | 16K | 4K | 512 |
| CH32V005 | 32K | 6K | 512 |
| （CH32V006/007 档） | 62K | 8K | 512 |

目标侧 `Ld/Link.ld` 的 MEMORY 段是**三档注释切换，模板默认选中最后一档**：

```
MEMORY
{
/* CH32V002 */
/*
	FLASH (rx) : ORIGIN = 0x00000000, LENGTH = 16K
	RAM (xrw)  : ORIGIN = 0x20000000, LENGTH = 4K
*/

/* CH32V004_CH32V005 */
/*
	FLASH (rx) : ORIGIN = 0x00000000, LENGTH = 32K
	RAM (xrw)  : ORIGIN = 0x20000000, LENGTH = 6K
*/

/* CH32V006_CH32V007_CH32M007 */
/**/
	FLASH (rx) : ORIGIN = 0x00000000, LENGTH = 62K
	RAM (xrw)  : ORIGIN = 0x20000000, LENGTH = 8K

}
```

- 转 **V002** → 启用第 1 档（16K/4K），`__stack_size` 改 512。
- 转 **V005** → 启用第 2 档（32K/6K），`__stack_size` 改 512。
- 保持默认第 3 档 = 拿到一颗不存在的芯片配置（62K/8K），**编译期零提示**。

> 🔴 无论工程级转换是否已经处理好这一项，都要在阶段 1 逐一核对「注释档位」与「`__stack_size`」是否与目标型号匹配。

## 3. `.highcode` 段 —— V003 独有

V003 侧 `Ld/Link.ld` 有 `.highcodelalign` 与 `.highcode` 两个段，用于把代码从 Flash 搬到 RAM 执行：

```
.highcodelalign : { ... PROVIDE(_highcode_lma = .); } >FLASH AT>FLASH
.highcode :
{
    PROVIDE(_highcode_vma_start = .);
    *(.highcode);
    *(.highcode.*);
    PROVIDE(_highcode_vma_end = .);
} >RAM AT>FLASH
```

配套：V003 的 `Startup/startup_ch32v00x.S` 有把该段从 Flash 拷到 RAM 的启动代码
（`la a0, _highcode_lma` / `la a1, _highcode_vma_start` / `la a2, _highcode_vma_end`）。

**目标侧整体不存在这一套**：`Link.ld` 无该段，`startup_ch32v00X.S` 无搬运代码。

| 用户代码情况 | 表现 | 处理 |
|---|---|---|
| 用了 `__attribute__((section(".highcode")))` | **链接期**才报错（找不到段） | 需重定向或删除该属性 |
| 调用 V003 带 `.highcode` 的函数（如 `WFE()`） | 编译期报未声明 | 见 `08_core-riscv.md` |
| 完全没用 | 无影响 | — |

> 🔴 这是"编译期可能零提示、链接期/上机才炸"的一类，规则文件未覆盖，属实测补充。

## 4. 芯片宏

目标侧（`ch32v00X.h:19-24`）在未定义任何宏时**默认落到 `CH32V006`**，宏集合为：

`CH32V002` / `CH32V004` / `CH32V005` / `CH32V006` / `CH32V007_M007`

**工程级转换会按目标型号建立对应芯片的工程，因此转换后工程不需要 skill 再显式写芯片宏。**
skill 只需核对工程实际生效的芯片宏与用户指定的目标型号一致（不一致时停下报告）。

## 5. 库文件命名

| | V003 侧 | 目标侧 |
|---|---|---|
| 外设库 | `ch32v00x_*.c/h`（小写 x） | `ch32v00X_*.c/h`（大写 X） |
| 用户系统文件 | `system_ch32v00x.c/h` | `system_ch32v00X.c/h` |
| 中断文件 | `ch32v00x_it.c/h` | `ch32v00X_it.c/h` |
| 配置 | `ch32v00x_conf.h` | `ch32v00X_conf.h` |
| include guard | `__CH32V00x_GPIO_H` 等 | `__CH32V00X_GPIO_H` 等 |

Windows 文件系统大小写不敏感，`#include <ch32v00x_tim.h>` 在目标工程里**可能不报错**。
不要依赖这个行为，阶段 2 统一把 include 改成大写 X 形态。

## 6. 工程结构与基线

单个模板工程（以 `GPIO/GPIO_Toggle` 为例）的文件集合，两侧一一对应：

```
<Project>/
├── .cproject .project .template <Project>.wvproj
└── User/
    ├── main.c
    ├── system_ch32v00x.c / .h     ← 目标侧 system_ch32v00X.c / .h
    ├── ch32v00x_it.c / .h         ← 目标侧 ch32v00X_it.c / .h
    └── ch32v00x_conf.h            ← 目标侧 ch32v00X_conf.h
```

外设库、启动文件、链接脚本、`Debug/` 由工程级转换建立，位于工程外或 `SRC/` 下，不属于 `User/`。

### 系统时钟默认档位（两侧不同）

`User/system_ch32v00x.c` 顶部是 6 选 1 的注释切换，**模板默认档位不同**：

| | 默认启用 |
|---|---|
| V003 侧 | `SYSCLK_FREQ_48MHz_HSE`（第 25 行） |
| 目标侧 | `SYSCLK_FREQ_48MHz_HSI`（第 22 行） |

两档都是 48MHz，但**时钟源从 HSE 变成 HSI**。若客户工程的主频/时钟源与源工程不同，
必须显式改这一行；两侧都靠 `SystemCoreClock` 对外暴露，改档后无需再改别处。

## 7. 工程属性：工具链与指令集扩展（转换后必须设置）

工程级转换完成后**立即**设置两条工程属性。由 MRS 智能体按自然语言执行，**不需要手工改工程文件**。

| # | 属性 | 取值 |
|---|---|---|
| 1 | 工具链 | **GCC15** |
| 2 | 编译属性 | **关闭 M 乘法扩展**；**开启 ZMMUL 扩展** |

### 7.1 为什么必须显式设置

目标芯片核使用 **ZMMUL**（乘法子集），而源 V003 工程默认不带这一项：

| | 基础架构 | M 乘法扩展 | ZMMUL |
|---|---|---|---|
| V003 | `rv32e` | 关闭 | **无此项** |
| 目标侧 | `rv32e` | 关闭 | **开启** |

不设置时工程沿用源工程的指令集配置，**编译期不会报错** —— 属静默差异。
另：工具链沿用源工程时也可能与目标侧不一致，故两项一并显式设置。

### 7.2 执行方式

**由 MRS 智能体按自然语言描述设置，不读工程文件、不手工改工程文件。** 转换完成后立即执行一次，共两条：

> 把当前工程的工具链切换为 GCC15；在编译属性里关闭 M 乘法扩展，勾选 ZMMUL 扩展。

设置完即视为完成，不需要再去核对工程文件中的落盘字段。
