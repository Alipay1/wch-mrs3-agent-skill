# 函数 API 差异表

> 数据来源：「函数·原型」维度。两侧同名函数的**签名（返回类型 + 形参类型）零冲突**，
> 差异仅剩「仅单侧存在」与「形参命名不同（接口等价，无需改动）」。

## 一、结论

| 项 | 数值 |
|---|---:|
| STM32 侧原型总数 | 403 |
| CH32 侧原型总数 | 422 |
| 签名冲突（同名不同签名） | **0** |
| 仅 STM32 存在 | 25 |
| 仅 CH32 存在 | 44 |

调用点无需改动形参顺序、类型或返回值处理。

> ⚠ **这条结论只对「签名」成立。** 函数体内部的行为差异不在本文件 ——
> 见 `references/08_func-behavior.md`：归一化后仍不一致的条目共 **76** 条，
> 全部属于「**调用点不用改、但行为会变**」那一类，编译器不会给出任何提示。
> 换句话说，本文件说「不会被编译器拦下」，08 说「那怎么办」。

### 内容有差异的初始化结构体

| 模块 | 结构体 | 说明 |
|---|---|---|
| adc | `ADC_InitTypeDef` | STM32 6 个成员，CH32 8 个成员：多出 `ADC_OutputBuffer`、`ADC_Pga` 两个（运放/输出缓冲配置）。旧代码按位置初始化时多余成员默认为 0，不影响 |

### 非初始化用途的结构体差异

寄存器结构体（`XXX_TypeDef`）的成员名几乎全改，共 22 个有差异、1 个完全一致
（`CAN_FilterRegister_TypeDef`）。**逐成员对照见 `references/02_structmap.md`**，
此处不再重复计数——其中 `TIM_TypeDef` 含匿名 union、`FLASH_TypeDef` 有寄存器增删，
简单计数会产生误导，以 02 文件的手工核对表为准。
