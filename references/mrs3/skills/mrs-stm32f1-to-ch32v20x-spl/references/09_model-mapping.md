# F103 ↔ CH32V203 型号与封装映射

> 本文件**手工维护**，不由 `build_skill_data.py` 产出。
>
> 数据来源：
> - V203 侧：`CH32V20xEVT/EVT/EXAM/SRC/Peripheral/inc/ch32v20x.h` 型号宏注释；CH32V203 数据手册 §2.1 型号对比表
> - F103 侧：STM32F10x 标准外设库 `stm32f10x.h` 密度宏说明
> - WCH 官方选型页
>
> ⚠ 型号的电气参数、引脚定义、定时器通道数须查 CH32V203 数据手册，本文件不复制。封装与容量以官方最新选型表为准。

## 一、转换第一步：先定型号，再动代码

型号决定 `CH32V20x_*` 型号宏、可用外设实例与中断号。**先定型号再改代码**——型号宏错会导致外设实例与中断号成片缺失，后期返工成本远高于先花五分钟确认。

### 1.1 匹配规则（按封装）

1. 读源工程的芯片型号：`Project.uvprojx` 的 Device 字段，或由用户告知。
2. **按封装找候选** —— 引脚数是硬约束，选错无法直接替换。
3. 核 Flash / SRAM：V203 候选容量**小于**源型号时，必须提示用户评估代码体积。
4. 封装无对应时**停止并降级提示**（见第二节），不自行改封装、不建议换引脚。

### 1.2 按封装的对应关系

| 源封装 | STM32F103 常见型号 | V203 候选 | 状态 |
|---|---|---|---|
| LQFP48 | C6T6 / C8T6 / CBT6 | CH32V203C6T6 / C8T6 | ✅ 直接对应 |
| LQFP64 | R8T6 / RBT6 / RCT6 | CH32V203RBT6（LQFP64**M**） | ⚠ 封装代号不同，须核对引脚间距与 PCB 焊盘 |
| LQFP100 | V8T6 / VBT6 / VCT6 / VET6 | — | 🔴 **CH32V203 侧无此封装** |
| LQFP144 | ZCT6 / ZET6 | — | 🔴 **CH32V203 侧无此封装** |
| 其他（QFN / TSSOP） | — | 按 §1.3 表逐型号核对 | 逐项核对 |

**同封装但容量不等时的提示**（必须显式告知用户，不要静默替换）：

| 源型号 | 源容量 | V203 候选 | 差异 |
|---|---|---|---|
| STM32F103C6T6 | 32K / 10K | CH32V203C6T6 | 持平 |
| STM32F103C8T6 | 64K / 20K | CH32V203C8T6 | 持平 |
| STM32F103CBT6 | 128K / 20K | CH32V203C8T6 | ⚠ **Flash 减半** |
| STM32F103R8T6 | 64K / 20K | CH32V203RBT6 | ✅ 容量更充裕 |
| STM32F103RBT6 | 128K / 20K | CH32V203RBT6 | ✅ SRAM 增大 |
| STM32F103RCT6 | 256K / 48K | CH32V203RBT6 | ⚠ **Flash 减半、SRAM 增大** |

> F103 型号与其容量、封装的对应以 ST 官方选型表为准。上表覆盖常见型号，未列出的型号按 §1.3 的 V203 表反查。

### 1.3 CH32V203 全型号表

| 型号（短） | 订货型号 | 引脚 | Flash（零等待区） | SRAM | GPIO | 封装 |
|---|---|---:|---:|---:|---:|---|
| CH32V203F6 | F6P6 | 20 | 32K | 10K | 16 | TSSOP20 |
| CH32V203F8 | F8P6 / F8U6 | 20 | 64K | 20K | 17 | TSSOP20 / QFN20 |
| CH32V203G6 | G6U6 | 28 | 32K | 10K | 24 | QFN28 |
| CH32V203G8 | G8R6 | 28 | 64K | 20K | 24 | QSOP28 |
| CH32V203K6 | K6T6 | 32 | 32K | 10K | 26 | LQFP32 |
| CH32V203K8 | K8T6 | 32 | 64K | 20K | 26 | LQFP32 |
| CH32V203C6 | C6T6 | 48 | 32K | 10K | 37 | LQFP48 |
| CH32V203C8 | C8T6 / C8U6 | 48 | 64K | 20K | 37 | LQFP48 / QFN48 |
| CH32V203RB | RBT6 | 64 | 128K | 64K | 51 | LQFP64M |

要点：

- **V203 侧最大封装是 LQFP64M（64 引脚）**，没有 LQFP100 / LQFP144。
- Flash 列是**零等待运行区** `R_OWAIT`。V203 物理 Flash 为 224K，其余 `224K − R_OWAIT` 是**非零等待区**（见 §3.2）。
- RB 型号（128K / 64K）支持用户字配置，可在 `(128K+64K)` / `(144K+48K)` / `(160K+32K)` 三种组合中选择一种。

### 1.4 型号宏对照

| 源密度宏 | 源 Flash 范围 | V203 型号宏 | 说明 |
|---|---|---|---|
| `STM32F10X_LD` | 16–32K | `CH32V20x_D6` | |
| `STM32F10X_MD` | 64–128K | `CH32V20x_D6` | **C8T6 / CBT6 / RBT6 属此档** |
| `STM32F10X_HD` | 256–512K | `CH32V20x_D6` | V203 无同容量档，须评估裁剪 |
| `STM32F10X_XL` | 512–1024K | — | 🔴 无对应 |
| `STM32F10X_CL` | F105 / F107 | `CH32V20x_D8` / `D8W` | 互联型，外设差异大 |

V203 型号宏总览（来源 `ch32v20x.h`）：

```
CH32V20x_D6   → CH32V203F6 / F8 / G6 / G8 / K6 / K8 / C6 / C8
CH32V20x_D8   → CH32V203RBT
CH32V20x_D8W  → CH32V208
```

⚠ **D6 是设备头的默认值**（`ch32v20x.h:19-24`，`#if !defined(D8W) && !defined(D8) && !defined(D6)` 分支内）—— **V203 全系（D6）不需要任何配置，这是 WCH 官方默认路径**（EVT 中 176 个 D6 工程无一显式定义），**不要为此去改工程属性文件**。仅 **D8 / D8W** 须显式生效，改 `ch32v20x.h:20-22` 三行注释即可。详见 `05_migration-rules.md` 第二节第 4 项。

## 二、封装不匹配时的降级提示

V203 侧无对应封装时，**不要自行改封装、不要建议用户换引脚**，按以下话术输出（把 `{}` 替换为实际值）：

> CH32V203 系列**没有 LQFP100 / LQFP144 封装**，全系列最大为 LQFP64M（64 引脚）。
> 源工程使用 {封装}（{引脚数} 引脚），**无法在保持引脚兼容的前提下直接替换**。
> 可选路径：
> 1. 评估能否裁剪到 ≤64 引脚的 V203 型号（需重做 PCB 与引脚分配）；
> 2. 改用同封装的其他 CH32 系列（**本技能未覆盖，需另行比对**）；
> 3. 你指定目标型号，我按该型号继续比对。

**同封装换代号时必须说明**：`LQFP64`（STM32）→ `LQFP64M`（WCH）属于封装代号不同。两者引脚数与功能兼容，但**落地前须核对引脚间距与 PCB 焊盘**，不要默认可直接贴装。

## 三、芯片级差异（型号选定后仍须知道）

| 项 | STM32F103C8T6 | CH32V203C8T6 |
|---|---|---|
| 系统主频 | 72 MHz | **144 MHz** |
| APB1（FPCLK1） | **36 MHz** | **144 MHz** |
| CAN 与 USB | **不能同时使用** | **可同时使用** |
| JTAG | 支持 | **不支持**（2 线 SDI / WCH-Link） |
| Standby 唤醒 | 仅 PA0 | **所有 IO**（须配事件模式） |
| 工作电压 | 2.0–3.6 V | **2.4–3.6 V**（额定 3.3 V） |
| USB | USBD | USBD + **USBHD** |
| OPA / Touchkey | 无 | **有**（数量按型号） |
| LQFP48 管脚 | — | 与 STM32F103C8T6 **兼容** |

### 3.1 🔴 FPCLK1 从 36 MHz 提到 144 MHz —— 会改变既有代码的行为

STM32 的 APB1 上限 36 MHz，CH32V203 的 APB1 **可达 144 MHz**。两个后果：

- 目标库中依赖 `PCLK1 ≥ 60 MHz` 的分支**迁移后会真正生效**。典型例子是 `I2C_Init` 的
  `if (freqrange >= 60) freqrange = 60;` —— 在 STM32 上永远走不到，在 CH32V203 上**会生效**。
  详见 `08_func-behavior.md`。
- 用户代码若按「APB1 = 36 MHz」硬编码了预分频或时序参数，**迁移后必须重算**。

### 3.2 Flash 等待与主频

| | STM32F103C8T6 | CH32V203C8T6 |
|---|---|---|
| 等待周期 | <24 MHz 零等待<br>24–48 MHz 一等待<br>48–72 MHz 两等待 | 标称 Flash（零等待区）**各主频均零等待** |
| 配置方式 | 用户代码设 `FLASH_SetLatency()` | **用户无需配置**。启动文件把内核 CSR `0xBC0` 写 `0x1F`（流水线 + 指令预测全开） |
| 超频注意 | — | 🔴 **主频 >120 MHz 时操作非零等待区 Flash / 用户字 / 厂商配置字 / Boot 区，须先把 HCLK 二分频**，完成后恢复，保证 FLASH 操作频率 ≤100 MHz |

> `0xBC0` 的含义见启动文件注释 `Configure pipelining and instruction prediction`。
> STM32 侧对应的 `FLASH_SetLatency` / `FLASH_PrefetchBufferCmd` 等四函数在 CH32 侧**不存在**，处理方式见 `05_migration-rules.md` 的 FLASH 专项。

### 3.3 Flash 擦除后的读回值

STM32F103 擦除后字读 `0xFFFFFFFF`；CH32V203 擦除后**字读 `0xe339e339`**，半字读 `0xe339`，偶地址读 `0x39`、奇地址读 `0xe3`。这是外挂 Flash 加了一层加密处理所致，**不是故障**，也不要据此判定擦除失败。

- **不覆盖**外设符号替换（→ `01_regmap` / `02_structmap`）、语义差异（→ `03` / `05`）、函数实现层（→ `08`）。
